## 可以确认与尚未确认

- MONET 的 DROP 来自 `style_frame_store.dropped`，是累计队列/抓帧丢弃数。六槽耗尽、抓帧不完整或抓帧写响应错误均可能增加它。它不是显示欠载数，也不是每秒丢帧数。
- 摄像头约 30 fps、处理约 14～15 fps 时，稳态每秒约 15～16 个输入帧不能进入处理队列是预期的。完整旧版日志也存在约 22～23 drop/秒与 6～7 NN fps 的对应关系。当前视频的 OSD 更新窗口有限，不能用拍屏差值精确反推传感器帧率。
- `style_display` 对当前 epoch/行/像素坐标不匹配或缺少数据输出黑色；左右画面共用显示读路径，所以显示供数延迟是首要排查对象。持续落后时仍读取过期行会使恢复更慢。
- `DISP 60` 只证明输出同步刷新事件为 60 Hz，不证明所有显示像素供给完整。`ERR 0` 也不包含显示欠载计数。
- 现有显示读只提前一行发出请求；CNN 与显示之间仍是单 outstanding，强制 CNN 公平授权可能在显示紧急时带来等待。实际 DDR 返回抖动、显示读仲裁、过期行积压和帧槽切换需要进一步区分。
- 之前实板快照的 UF=0 对应 **6～7 fps 的固定显示优先版本**，不能用于当前版本。现有 640×480 仿真只包含一帧密集抓帧和行为 DDR，不能覆盖持续 30 fps 采集、CPU 外层竞争和物理 DDR 的全部抖动。
- 本轮无当前板端 UART，串口枚举只发现 COM1；未连接、复位、烧录或读取开发板。视频不能单独证明欠载，更不能排除拍屏效应或其他显示问题。

## 已补充的诊断固件

保留 MONET 和 DDR100M 行，新增每个日志间隔一行：

```text
VIDEO UF 0 DUF 0 DDROP 16 FAULT 0 CSI 0 DME 0 IERR 0 AXI 0
```

| 字段 | 来源/语义 |
| --- | --- |
| UF | `0xf810014c`，core 域显示 underflow 上升沿累计；不是缺失像素数或坏帧数 |
| DUF | 两次 VIDEO 日志之间 UF 的无符号差值 |
| DDROP | 两次 VIDEO 日志之间 style DROP 的无符号差值 |
| FAULT | `0xf8100140` 故障锁存位图，以十进制输出；bit2 对应显示欠载 |
| CSI | `0xf810015c`，现有 CSI 错误状态/位图，不应当作错误帧率 |
| DME | `0xf810024c` 显示行 DMA 错误累计 |
| IERR | `0xf8100244` 流式推理失败累计 |
| AXI | `0xf8100148` 外层 CPU/video 桥 AXI 错误累计 |

DUF/DDROP 是日志间隔内增量；日志通常约 1 秒，但包含 UART/OSD 服务时间，因此不能直接当作精确每秒率。第一次读数以 0 为基线，重载 ELF 也会重建软件基线；首行应忽略。32 位减法支持一次计数回绕，运行中另行清零硬件计数会使增量失效。

只增加固件读取已有寄存器和 UART 文本，复用原 224 字节日志缓冲。RTL、FPGA 存储、网络、权重和原发布 bitstream 均未改动；不需要重新综合或配置 FPGA。固件应与 `reports/style_demo/release_ddr_opt/ti60f225_oob.bit` 配套，独立 ELF/BIN 位于 `reports/style_demo/flicker_diagnostics/`，尚未下载到板上。

## 预取实验与下一步

本轮尝试在相同 FIFO 容量下把显示请求从提前 1 行改为提前 4 行。完整显示回归可恢复，但额外的同种子单帧对照中，在显示行 165 开始注入 5000 个 100MHz 周期（50 us）的返回停顿，两种预取提前量都得到 604800 个正确像素、9600 个欠载黑色像素，4800 个读突发且 DMA 错误为 0。此实验没有 CNN、CPU 或真实 DDR，只检验中途延迟的恢复；因此不能以提前请求宣称解决实板黑块，已撤回该 RTL 改动。512 项像素 FIFO 只保存约 0.4 个 1280 像素显示行，提前发出请求不等于能够缓存四行。实验源与日志保存在 `reports/style_demo/flicker_diagnostics/`，不能作为待烧录版本。

取得至少 30 秒当前版本 UART，并对照肉眼黑块发生时刻：

1. DUF 增长、DME/AXI/CSI 不增：优先检查显示期限和仲裁等待。对照使用现有固定显示优先版本确认吞吐/稳定性取舍；进一步用持续抓帧、CPU 竞争、DDR 延迟突发的仿真约束紧急授权和过期行丢弃策略。
2. DUF 不增、DME 或 AXI 增长：先处理 DDR/AXI 返回错误。
3. CSI 或采集 FAULT 增长：检查输入链路、抓帧背压与复位。
4. 所有相关计数平稳而肉眼仍闪：检查帧槽切换/显示有效标志和 HDMI 输出；若只有拍屏存在黑带，再验证手机快门/显示扫描效应。

不能通过清零 DROP、单纯重复最后一个像素或盲目增 RAM 宣称解决闪烁。维持上一完整帧需要可持续读到完整帧；当前显示槽已保持上一完整结果，单纯改变槽选择不能补齐实时 DDR 读出的像素。
