# 新发现：burst 长度上限 32 beat 导致 AR 握手过多

> 日期：2026-10-21
> 方法：**纯离线分析**（RTL 阅读 + 逐层计算）
> 结论：**burst 上限 32 beat 使全帧产生 29,880 次 AR 握手；放宽到 256 beat 可减 85%**

---

## 一、核心发现

### RTL 证据（`style_axi_rows.sv:20-28`）

```verilog
function [7:0] burst_len;
  input [15:0] remaining; input [31:0] address;
  reg [8:0] boundary; reg [15:0] n;
  begin
    boundary = (13'd4096 - {1'b0,address[11:0]}) >> 4;   // 不跨 4KiB
    n = remaining > 32 ? 32 : remaining;                 // ⚠️ 硬编码 32 上限
    if(n > boundary) n = boundary;
    burst_len = n - 1;
  end
endfunction
```

**两个限制**：
1. **`n = remaining > 32 ? 32 : remaining`** —— burst 最长 **32 beat = 512 B**
2. **`no 4KiB crossing`** —— 不能跨 4 KiB 边界

**而 `arlen` 是 8 bit（`output reg [7:0] arlen`）**，**支持到 256 beat** —— 硬件上放得开，只是代码写死了 32。

## 三、为什么这很关键

| 关联 | 说明 |
|---|---|
| **AR 等待 = 45.9%** | PROFILE 实测，是最大单项 |
| **每个 burst = 1 次 AR 握手** | 每次握手都要过仲裁 |
| **burst 减少 85%** | → **AR 握手减少 85%** → AR 等待大幅下降 |

**这是目前发现的、能直接打击「AR 等待 45.9%」的唯一手段，而且不需要额外 RAM。**

---

## 四、与已有发现的关系

| 现象 | 由 burst 过长/过短解释 |
|---|---|
| `AR` 45.9% | 29,880 次握手，每次都要仲裁 |
| `RGAP` 16.5% | 每个 burst 之间有空隙 |
| `core_busy` 恒定 77,450 | 总周期由 DDR 交互次数决定 |
| **预取扩展无效**（方向 A） | 预取只是提前发读，**burst 数不变** |
| **1×1 tap 无浪费**（方向 B） | 算力本来够，瓶颈在 DDR 交互 |

**统一解释**：所有问题的根源是 **DDR 交互次数太多**，而非算力或数据量。

## 五、实施方案

### 改动点（微小）

| 文件 | 改动 | 行数 |
|---|---|---|
| **`style_axi_rows.sv`** | `n = remaining > 32 ? 32 : remaining` → `n = remaining > 256 ? 256 : remaining` | **1 行** |
| `program.py`（可选） | src 地址 4 KiB 对齐 | 少量 |
| `program.vh`（可选） | 重新生成 descriptor | 自动 |

### 关键约束核实

| 项 | 状态 |
|---|---|
| `arlen` 8 bit 支持 256 beat | ✅ **已确认**（`arlen=255` 表示 256 beat） |
| AXI INCR 最大 256 beat | ✅ AXI 规范允许 |
| 不跨 4 KiB | ⚠️ **需地址对齐**，否则仍会被切 |
| DDR3 控制器支持长 burst | ❌ **未验证** |
| 显示读是否被饿死 | ❌ **未验证**（长 burst 占用读通道更久） |

### 行字节与 4 KiB 页

| 层 | 行字节 | 每行 burst（4KiB 对齐后） |
|---|---|---|
| 0/1/21 | 2,560 B | **1** |
| 2 | 1,280 B | **1** |
| **3–19** | 3,840 B | **1** |
| 20 | 7,680 B | **2** |
| 22 | 5,120 B | **2** |

**注意**：所有行字节都**不是** 4 KiB 的整数倍（2,560 / 3,840 / 7,680 / 5,120）。
所以即使 4 KiB 对齐，**相邻行会跨边界** —— 但**单行本身**（<4 KiB 或刚好 2 页）可以 1–2 个 burst 读完。

## 七、风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| **显示欠载** | 长 burst 占用读通道更久，显示可能饿死 | **与 UOF=0 一起调** |
| DDR 控制器不支持 | 未验证 | 先查 DDR 控制器 RTL 的 burst 处理 |
| 延迟增加 | 单次 burst 更长 → 首字节延迟不变但整体占用更久 | 需要仲裁配合 |
| 整数正确性 | 只改 burst 长度，不改数据 | 风险低（可用 iverilog 验证） |
