# 我们的改动能否完全迁移到新架构（feature/resource_optimize）

> 日期：2026-10-20
> 结论：**可以完全迁移。P0 零冲突（纯文件复制），P1 需一行适配**

---

## 一、我们的改动分三层

| 层 | 内容 | 数量 | 与 RTL 的关系 |
|---|---|---|---|
| **P0 训练产物** | `rtl/style/model/*` | **8 文件** | RTL **直接消费** |
| **P0 训练代码** | `tools/analysis/*.py` | **9 跟踪 / 92 磁盘** | **纯 PyTorch，零 RTL 依赖** |
| **P0 训练报告** | `reports/ink/*.md` + 模型 `.pt` | 19 md | 文档 |
| **P1 RTL 改动** | `style_network.sv`（is_last）、`style_display.sv`（单面板） | 2 文件 | **需适配** |

**关键前提（实测）**：`_train_v2.py` **未引用任何 `rtl/`** → 训练与 RTL **完全解耦**。

---

## 二、P0：零冲突，直接复制

### 2.1 训练是纯 PyTorch

| 检查 | 结果 |
|---|---|
| `_train_v2.py` 引用 `rtl/` | ❌ **0 处** |
| 依赖 | torch / torchvision / PIL / numpy |
| 远端是否有等价训练脚本 | ❌ **无**（`tools/analysis` 远端 0 文件；远端只有 `ml/style_transfer/train.py`，**与我们不同源**） |

**→ 训练脚本可整目录搬过去，不与新架构冲突。**

### 2.2 训练产物格式兼容（**已逐位核实**）

| 文件 | 我们 | 远端 | 兼容 |
|---|---|---|---|
| `model.bin` | 11,056 B | 11,056 B | ✅ **同尺寸、同格式**（哈希不同 = 不同权重，非格式差异） |
| `program.hex` | 966 B | 966 B | ✅ |
| `program.vh` | 1,915 B | 1,915 B | ✅ **同格式**（头部逐字相同） |
| `style_weights.h` | 76,953 B | 76,953 B | ✅ |
| `coeff.bin` / `coeff.hex` | 24,576 / 49,664 | 同 | ✅ |

**`program.vh` 的唯一差异**（逐位比对得出）：

| | descriptor 22（最后一层） |
|---|---|
| **我们** | `...0001...` ← **设了 bit132** |
| **远端** | `...0000...` ← 未设 |

**其余 22 个描述符逐字相同。**

### 2.3 descriptor 位域定义**完全一致**

| 位域 | 我们 | 远端 |
|---|---|---|
| `ci` | `[4:0]` | `[4:0]` ✅ |
| `co` | `[9:5]` | `[9:5]` ✅ |
| `kernel3/dw/stride2/up2/residual/relu` | `[15:10]` | `[15:10]` ✅ |
| `iw/ih/ow/oh` | `[19:16]` | `[19:16]` ✅ |
| `weight_base/norm_base` | `[35:20]` | `[35:20]` ✅ |
| `src` | `[67:36]` | `[67:36]` ✅ |
| `dst` | `[99:68]` | `[99:68]` ✅ |
| `skipaddr` | `[131:100]` | `[131:100]` ✅ |
| **`bit132`** | **`is_last`** | **空闲未用** ✅ |

**→ 我们的 is_last 用的是远端**预留未用**的位，格式上零冲突。**

## 三、P1：只有 2 个 RTL 文件需适配

### 3.1 `style_network.sv` —— 一行差异，**语义冲突**

| | `dst` 判定 |
|---|---|
| **我们** | `dst = is_last(descriptor[132]) ? result_address : descriptor[99:68]` |
| **远端** | `dst = layer_index==22 ? result_address : descriptor[99:68]` |

| 方式 | 层数灵活性 |
|---|---|
| 我们（bit132） | ✅ **任意层数**（head 或其它层可追加） |
| 远端（硬编码 22） | ❌ **固定 23 层** |

**适配方案（推荐）**：在新架构上用**我们的版本**（含 `is_last`），
并在 `program.vh` 的 descriptor 22 补上 bit132。
**代价：1 行 RTL + 1 处 descriptor 位**。

### 3.2 `style_display.sv` —— **远端是旧版，必须用我们的**

| | 显示模式 | DRB（实测） |
|---|---|---|
| **我们** | **单面板 640**（`IMG_X0=580`） | **4,695,168** |
| 远端 | 双面板 1280（`h 260..1540`） | 9,392,768 |

**远端自己注释说明双面板会「doubled the DDR read traffic」。**
**我们的版本显示读流量减半（实板实测）→ 必须保留我们的。**

| 内容 | 动作 |
|---|---|

## 五、`.gitignore` 陷阱（**最易漏的点**）

| 目录 | 磁盘 | git 跟踪 | 被 ignore |
|---|---|---|---|
| `tools/analysis` | **92** | **9** | **83** |
| `reports/ink` | 52 | 22 | 30 |

**含义**：`git` 只能带走 9 个训练脚本，**83 个（含 `_bw_eval.py`、`_v6_eval.py`、`_perf_cmp.py` 等全部评估/诊断脚本）不会跟随**。
`_data/黑白ink`、`*.pt` 模型同理。

**→ 迁移必须用 `cp -r` 复制这些未跟踪文件，或临时调整 `.gitignore`。**

## 六、结论

| 问题 | 答案 |
|---|---|
| **训练能否完全迁移？** | ✅ **可以**（纯 PyTorch，零 RTL 依赖） |
| **产物格式是否兼容？** | ✅ **完全兼容**（位域逐位一致） |
| **是否有冲突？** | ⚠️ **仅 2 处**（`style_network.sv` 一行 + descriptor 一位） |
| **迁移后能否复现我们的结果？** | ✅ 可以（脚本 + 产物 + 数据齐备） |
| **是否会回退远端优化？** | ⚠️ **若误用远端 `style_display.sv` 会**（DRB 翻倍） |

**一句话**：**模型训练部分可以【完全】迁移；RTL 侧需保留我们的 2 个文件（is_last + 单面板），其余用远端的。**
