## 三、⚠️ 这些数字的**归因限制**（报告自己声明）

### Lite 报告的原文警告

> 「Standard数字来自**已有 Windows 2026.1.132 构建**，Lite 是**本机 Linux 2026.1.132 新构建**，
> **未在本机重建 Standard 控制组**。XLR 变化包含**重生成版本、Lite 策略和布局打包影响**，
> **不能全部归因于 CDC**；RAM 减少 17 与原 CDC 占用及 SoC 层次变化一致。」

**含义**：−1,565 XLR 里**混了三样东西**（重新生成、Lite 策略、布局打包），
**不能全算作 CDC 移除的收益**。

### merged 报告的原文警告

> 「**不能简单相加三个独立工程的收益**；上述是合并版实际布局结果。」

**含义**：−801 XLR 是**合并后的实际值**，不能拆成"OSD 省 X、prefetch 省 Y"。

## 六、四项功能细节（读后结论）

### 1. Lite 统一时钟
- 用 Efinity 自带 Sapphire JAR：`--noDdrAClock --lowArea 5`
- **保留** M 扩展、桶形移位器、完整 CSR（不传 `--noMulDiv` 等）
- 删除专用 `io_memoryClk`，原 `io_memoryReset` 作为 `io_systemReset` 别名
- **SoC 层次 RAM 从 43 降至 26**，`system_ddr_ddrLogic_cc_fifo` 消失
- ⚠️ 限制：「未运行新 CPU RTL 指令仿真」「不证明新 Sapphire CPU、cache、PLIC RTL 等价」

### 2. OSD 紧凑字库
- 保留全部 95 个可打印 ASCII，非打印/未知字符输出**空白行**
- 「不改变字符页及同步延迟」

### 3. 采集统计位宽收窄
- 内部位宽按边界收窄，**对外 32 位字段、配置版本、冻结 META、CDC 语义保留**
- 证据：1920×1080 差分 7,359,692 周期、322 词直方图握手

### 4. CNN 安全预取
- 读算重叠，**保留不支持层的串行路径**
- 遥测 PF/PFC/OVLP，实测 PF=59、PFC=59、OVLP=987

## 十一、【重要发现】读/算串行是各版本共有的结构性瓶颈

### 来自远端仿真的诊断（`docs/DDR_READ_OPTIMIZATION.md`）

完整 640×480 帧测量窗口 **6,897,433 周期（100MHz）**：

| 项 | 值 | 占比 |
|---|---|---|
| **CNN 返回间隙（RGAP）** | **1,618,994** | **23.47%** ← **最大浪费项** |
| CNN AR 等待 | 765,790 | 11.10% |
| CNN W 等待 | 464,025 | 6.73% |
| 显示/CNN RREADY 反压 | **0** | 0 |
| 网络读阶段 | 5,447,882 | 36.686 ms |
| core busy | 4,713,227 | 31.739 ms |

**关键算术**：
```
读阶段 36.686 ms + core busy 31.739 ms = 68.425 ms
任务总时长                                 68.974 ms
                                          -----------
重叠部分                                  0.549 ms  （≈ 0.8%）
```

**即：读与算几乎完全【串行】。**

远端报告的原话：
> 「本场景解除显示接收反压后，**下一项值得评估的是读阶段与计算/输出阶段的重叠**；
> 不能只再增加仲裁逻辑就承诺更高帧率。」

### 用我们的实板遥测交叉验证（**同一结论**）

| 版本 | RPMS（读 ms） | CPMS（算 ms） | 和 | MS（单次推理） | 重叠 |
|---|---|---|---|---|---|
| 早期硬件 | 33 | 31 | 64 | 66 ms | 2 ms |
| release_deadline | 59 | 31 | 90 | 91 ms | 1 ms |
| **本次（ours）** | **45** | **31** | **76** | **78 ms** | **2 ms** |

**三个版本的 `RPMS + CPMS ≈ MS`**，误差都在 2 ms 内。

### 结论

**读/算串行是【所有版本共有】的结构性瓶颈**，不是某一版的缺陷。

| 含义 | 说明 |
|---|---|
| **面板/仲裁优化已达上限** | 显示反压已为 0，再调仲裁**不能再提速** |
| **唯一剩余的加速杠杆** | **读算重叠（prefetch）** |
| 潜在收益量级 | 若完全重叠 → 78 ms 降到 ~45 ms（**~1.7×**），即 **12 fps → ~20 fps** |
| **归属** | 这正是远端 `prefetch`（我们未取用）的功能 |

⚠️ **收益上限是估算，不是实测**：远端对 prefetch 只给了
`OVLP=987` 周期（32×24 短帧）与 `PFC=PF` 的完成计数，
**未给出全帧加速比**。其报告明确「不可外推成实板 FPS」。
