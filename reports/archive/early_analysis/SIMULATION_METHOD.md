> 日期：2026-10-14

## 1. 板上真实数据通路（从代码核实）

```
相机 RGB 双像素流
  ↓ 中心裁剪 1280×960
  ↓ 2×2 平均                        ← 真实的预滤波
  ↓ 存储 640×480 XBGR8888 到 DDR3
  ↓ 23 层 INT8 CNN（内部按 160×120 运算）
  ↓ 结果 640×480 写回 DDR3
  ↓ 显示：左 640 = 原图槽，右 640 = 结果槽
  ↓ 最近邻放大到 1280×720 活动区（h 260..1540, v 25..745）
  ↓ OSD 文字叠加
  ↓ HDMI 720p60
  ↓ 采集卡（1920×1080）
```

**证据来源**：

| 环节 | 出处 |
|---|---|
| 1280×960 裁剪 + 2×2 平均 | `docs/STYLE_DEMO_IMPLEMENTATION.md` |
| 640×480 INT8 推理，9,056,056 周期 | 同上（逐字对拍记录） |
| 活动区 h 260..1540, v 25..745 | `rtl/style/style_display.sv:16` |
| 720p60 时序（h==1649 / v==749） | 同上 |
| 左右双面板布局 | `style_display.sv` 的 `right_side` / `raw_base($slot)+0x800000` |

## 2. 模拟脚本做了什么

```python
def board_frame(photo):
    # ① 把照片当作相机的 1280×960 中心裁剪
    cam = resize(photo, 1280, 960)

    # ② 2×2 平均 → 640×480（与板上完全一致）
    x = average_2x2(cam)

    # ③ 真实整数网络（板上跑的就是这份）
    y = integer_network(x)

    # ④ 按采集卡实测到的几何排布
    frame[180:900, 0:959]    = resize_nearest(x, 959, 720)   # 左 = 原图
    frame[180:900, 959:1918] = resize_nearest(y, 959, 720)   # 右 = 结果
    return frame
```

**第 ④ 步的几何来自实测**——我早前抓真实 Monet 画面时测得：画面内容在 180..899 行，两个面板在 958 列附近相接，上下有黑边。

## 3. 各环节的保真度

| 环节 | 保真度 | 说明 |
|---|---|---|
| **INT8 CNN** | **完全精确** | 用真实导出的整数 oracle（`integer.py`），与 RTL 逐像素对拍过 |
| **160×120 瓶颈** | **完全精确** | 包含在 oracle 内部 |
| **2×2 平均** | **完全精确** | 本次新增（见下方修正说明） |
| DDR3 存取 | 无需模拟 | 内容保持型操作 |
| 照片 → 1280×960 | 近似 | 用双三次放大代替真实相机 |
| 显示放大 | 近似 | 采集卡另有自己的缩放 |
| OSD 文字 | 省略 | 不影响图像内容 |
| **相机 ISP / 伽马 / 噪声** | **未模拟** | 真实相机有 3A、去马赛克、伽马 |
| **HDMI / 采集卡色彩链** | **未模拟** | YUV 转换、量化范围 |

## 4. 我修正的一处错误

**上一轮的模拟漏掉了相机端的 2×2 平均。**

这是个真实的预滤波（板上确实做），我之前直接把照片缩放到 640×480，
少了这一步。

**量化影响**（10 张图）：

| 输入路径 | 输出差异 |
|---|---|
| 直接缩放 vs 2×2 平均 | **2.20 LSB** |

**修正后的结论**：这个遗漏影响很小（2.20 LSB，相对平均 |Δ| 15.92 是 14%），
不改变任何此前的结论。但**模拟已经改正**。

## 5. 模拟的可信度评估

### 5.1 高可信部分

| 项 | 为什么可信 |
|---|---|
| **网络计算** | 整数 oracle 与 RTL **逐像素对拍通过**（192 行 / 2976 像素） |
| **瓶颈效应** | 是 oracle 内在特性，不需要额外建模 |
| **效果方向** | 颜色偏移（ΔB +9.7）由网络权重决定，与平台无关 |

### 5.2 已知的偏差来源

| 来源 | 可能影响 |
|---|---|
| 相机 ISP（伽马/锐化/去马赛克） | 会改变输入分布，进而改变输出色调 |
| 采集卡 YUV 转换 | 可能有色度抽样与量化范围偏移 |
| 显示器色域/伽马 | 实际观感受此影响 |
| 样本差异 | 用的是数据集照片，不是真实相机帧 |

### 5.3 怎么用这个模拟

**适合回答**：
- ✅ 效果强度大概多少
- ✅ 颜色往哪个方向偏
- ✅ 有没有色带
- ✅ 与 Monet 的对比

**不适合回答**：
- ❌ 绝对色彩准确度
- ❌ 实际显示器上的观感
- ❌ 帧率/DDR3 时序问题

## 7. 更可靠的验证顺序

```
① 离线模拟（已完成）          ← 现在这里
      ↓  确认效果方向与强度
② 烧录 + 采集卡实测           ← 下一步
      ↓  确认端到端正确
③ 与模拟对比                  ← 校准模拟的可信度
```

**第 ③ 步很重要**：把实测结果与模拟对比，就能知道模拟的偏差有多大。
如果两者接近，以后可以用模拟快速评估新模型；如果差很多，说明相机 ISP 的影响显著。

## 附：一句话总结

> **模拟的「网络计算」部分是完全精确的**（真实整数 oracle，与 RTL 逐像素对拍过）；
> **「成像链路」部分是近似的**（未模拟相机 ISP 与 HDMI 色彩链）。
> 因此模拟适合判断**效果方向与强度**，不适合判断**绝对色彩准确度**。
