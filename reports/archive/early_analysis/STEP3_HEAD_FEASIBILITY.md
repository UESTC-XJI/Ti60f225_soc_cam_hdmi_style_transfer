# 步骤 3 可行性研究：全分辨率 3×3 头

> 日期：2026-10-14
> 目的：为「补高频细节（线条/纹样）」评估可行性
> 结论：**可行，但需要改 3 处 RTL/脚本，不是纯模型改动**

---

## 0. 结论

| 项 | 结论 |
|---|---|
| **算力** | 可接受（RF 7 方案 1.73×，约 **5.8 fps**；RF 3 方案 1.33×，7.5 fps） |
| **DDR** | ✅ 够（需 4.9 MB，空闲 **12.8 MB**） |
| **系数 ROM** | ✅ 够（+7 权重字，+5 归一化字，上限 256） |
| **片上 RAM** | ✅ 预期不改（复用现有行缓冲与系数 bank，需综合确认） |
| **RTL 改动** | ❌ **必须改 3 处硬编码** |

## 1. RTL 的硬约束（实读源码）

### 1.1 输入通道上限 24（`style_row_core.sv:22-23`）

```verilog
reg [63:0]  row0lo[0:MAX_WIDTH-1];      //  8 通道
reg [127:0] row0hi[0:MAX_WIDTH/2-1];    // 16 通道，合计 24
```

`read0/1/2` 拼成 **192 bit = 24 通道**。`out_data` 与 `skip` 也是 192 bit。

### 1.2 输出通道上限 32（`co_group` 是 2 bit）

```verilog
reg [1:0] column,co_group,red_group;      // co_group 只有 4 个值
wire [7:0] waddr=weight_base+co_group*red_groups+red_group;
```

每组 8 路 → **4 × 8 = 32 通道上限**。

### 1.3 非深度 3×3 只能是 ci=3（`style_row_core.sv:102-106, 117`）

```verilog
wire [95:0] rgb_terms=red_group==0 ?
    {patch[2][15:8],patch[1][15:8],patch[0][15:8], ... } : ...;
...
kernel3 ? rgb_terms[ac_tap*8+:8] : pw_terms[ac_tap*8+:8];
```

**`rgb_terms` 硬编码为 3 个输入通道**（每个 patch 字的 bit 0/8/16）。

**这意味着**：全分辨率的普通 3×3 卷积**只能写 `Conv3×3(3 → co)`**。
若要在全分辨率做更深的 3×3，**必须用 depthwise**（`dw_slice = patch[tap] >> (co_group*64)`）。

### 1.4 因此可行的头结构被限定为

```
Conv3x3(3 -> 8)          <- 唯一可能的全分辨率非深度 3x3
  ↓
[DWConv3x3 + Conv1x1] × n   <- MobileNet 式块
```

**感受野**：

| 结构 | RF |
|---|---|
| `Conv3x3 3→8` | 3 |
| + 1×(DW3x3, 1x1) | 5 |
| **+ 2×(DW3x3, 1x1)** | **7**（= 官方 7×7 头） |

## 2. 算力定价（基于项目实测周期）

**基准**：`docs/STYLE_DEMO_IMPLEMENTATION.md` 记录完整 VGA 推理 = **9,056,056 周期**。

| 指标 | 值 |
|---|---|
| 当前 MACs/帧 | 204,134,400 |
| 实测周期 | 9,056,056 |
| **有效 MAC/周期** | **22.5** |

> 有效率仅 22.5，远低于 96 路峰值 —— 项目已记录的 DDR 停顿与固定开销。

**候选头方案**：

| 方案 | 结构 | 新增 MACs | 比值 | 估算周期 | **帧率** | RF |
|---|---|---|---|---|---|---|
| C | `Conv3x3 3→8` | 66,355,200 | 1.33× | 11,999,785 | 7.5 fps | 3 |
| **B** | `+1×(DW3x3,1x1)` | 108,134,400 | 1.53× | 13,853,244 | **6.5 fps** | 5 |
| **A** | `+2×(DW3x3,1x1)` | 149,913,600 | **1.73×** | 15,706,703 | **5.8 fps** | **7** ✅ |
| D | 16 通道版 | 351,436,800 | 2.72× | 24,646,918 | 3.7 fps | 7 |

**推荐方案 A**（RF 7，匹配官方）：代价 1.73×，帧率约 **5.8 fps**。

**为什么比之前估的 1.95× 便宜**：早先版本用的是 4 通道 + 直接把 3×3 全宽卷积
堆叠（`3→4→4→8` 都是非深度），但 **RTL 不允许 ci≠3 的非深度 3×3**（§1.3）。
改用 depthwise 后，代价降到 1.73×。

## 3. DDR 分析（修正了我的一次算错）

### 3.1 固定的 4 个缓冲区（`program.py:8`）

```python
f0,f1,f2,big = 0x06000000, 0x060A0000, 0x06120000, 0x06200000
```

预留 `0x06000000 .. 0x07000000` = **16.78 MB**。

### 3.2 我的一次建模错误（已修正）

我最初把 4 个基址之间的空隙当作**硬性槽位**，于是报告 dec.2 溢出。

**这是错的**。实测：

```
dec.2 -> f1 (0x060A0000)，写出 2.4576 MB
      该区间跨越 f2 与 big —— 但此时 f2/big 都已死亡
      （dec.0 的输出已被 dec.1 消费）
```

**4 个缓冲是有意重叠（alias）的**，不是固定分区。

### 3.3 正确的用量

| 缓冲区 | 最大需求 | 来源 | 写入次数 |
|---|---|---|---|
| `0x06000000` | 0.6144 MB | enc.0 | 10 |
| `0x060A0000` | **2.4576 MB** | dec.2 | 6 |
| `0x06120000` | 0.4608 MB | res.0.1 | 5 |
| `0x06200000` | 1.8432 MB | dec.0 | 1 |

**最高实际写入地址**：`0x063C2000` = 起点 + **3.940 MB**

**空闲**：`0x063C2000 .. 0x07000000` = **12.837 MB**

### 3.4 头的需求

| 项 | 大小 |
|---|---|
| 一个全分辨率 8 通道特征图 | 8 × 640 × 480 = **2.458 MB** |
| 双缓冲（ping-pong） | **4.915 MB** |
| 空闲 | **12.837 MB** |

**✅ 够用。**

## 4. 系数 ROM 分析

权重区 `0..127`，归一化区 `128..255`（每 bank 256 字）。

当前占用：`weight_base` 最大 **85**，`norm_base` 最大 **186**。

方案 A 新增：

| 层 | ci | co | k | dw | 权重字 | 归一化字 |
|---|---|---|---|---|---|---|
| head.0 | 3 | 8 | 3 | 否 | 3 | 1 |
| head.1 | 8 | 8 | 3 | 是 | 1 | 1 |
| head.2 | 8 | 8 | 1 | 否 | 1 | 1 |
| head.3 | 8 | 8 | 3 | 是 | 1 | 1 |
| head.4 | 8 | 8 | 1 | 否 | 1 | 1 |
| **合计** | | | | | **+7** | **+5** |

**85 + 7 = 92 < 128** ✅
**186 + 5 = 191 < 256** ✅

**注**：`weight_base` 是 8 bit，**实际硬件上限是 255**（权重与归一化共用一个 256 字空间）。
`export.py` 里 `norm_cursor=128` 只是**约定**，不是硬件限制。

## 5. 必须改的 3 处硬编码（真正的阻碍）

### 5.1 `ml/style_transfer/program.py:8-14`

```python
f0,f1,f2,big=0x06000000,0x060A0000,0x06120000,0x06200000
pairs=[(0,f0,0),(f0,f2,0),(f2,f1,0)];current=f1
for b in range(4):
    other=f2 if current==f1 else f1
    pairs.extend([(current,f0,0),(f0,other,0),(other,f0,0),(f0,other,current)]);current=other
pairs.extend([(current,big,0),(big,f0,0),(f0,f1,0),(f1,0,0)])
inlevels=[0,1,2]+[2]*16+[2,1,1,0];outlevels=[1,2,2]+[2]*16+[1,1,0,0]
```

**问题**：
- 手工写死 23 条 `pairs`
- `inlevels`/`outlevels` 是**字面列表**，长度恰好 23

**改法**：改为按图自动规划（分配器 + 分辨率层级推导）。

### 5.2 `rtl/style/style_network.sv:26, 107`

```verilog
wire [31:0] dst=layer_index==22 ? result_address:descriptor[99:68];
...
if(layer_index==22) begin busy<=0;done<=1;state<=IDLE;end
```

**末层判定是字面量 22**。加入头之后，末层索引会变。

**改法**：改为参数或由描述符携带「是否末层」标志。

### 5.3 `rtl/style/style_row_core.sv:117`（限制，不是硬编码）

见 §1.3 —— 这个**不需要改**，只要把头的结构限定为
「`Conv3x3(3→co)` + depthwise 块」即可。

## 7. 与 v6/v7 训练改进的关系

**两件事互不替代**：

| 措施 | 解决 |
|---|---|
| v6/v7 训练改进 | 暗场过亮、identity 过强 |
| **步骤 3（3×3 头）** | **高频/线条缺失（当前只有官方的 82%）** |

**实测证据**（8 张验证图）：

| 样本 | edge | hf |
|---|---|---|
| 真实浮世绘 | 162.95 | 14.20 |
| official | 180.98 (111%) | 14.60 (103%) |
| **v6** | 169.26 (104%) | **11.70 (82%)** |

**hf（高频）只有 82%，这是"不像浮世绘"的直接原因。**
