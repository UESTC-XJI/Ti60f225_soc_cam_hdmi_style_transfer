## 二、板侧实测数据

### 2.1 DDR 里风格帧的真实分布

从风格帧缓冲区（`0x05800000 + slot*0x140000`）读**完整一行 640 像素**（行 240）：

| 通道 | 均值 | **σ** | 范围 | 水平相邻差 |
|---|---|---|---|---|
| **R** | **28** | **23.0** | 0 – 121 | 2.25 |
| G | 26 | **44.9** | 0 – 154 | 1.90 |
| B | 12 | **26.1** | 0 – 102 | 1.28 |

> 注意：R/G/B 三个通道的均值和 σ 都**不一样**，说明色彩通道之间的分布差异很大。这本身可能是个问题（见 §4.2）。

### 2.2 关键：均值 +28 意味着没有居中

INT8 的满量程是 **−128..+127**，中性灰应该对应 **0**。

**实测 R 均值 = +28，偏离中心 28/127 ≈ 22% 满量程。**

显示端把 INT8 当无符号处理（`display = stored ^ 0x80`，即 +128 偏移），所以：

- 期望：均值 0 → 显示 128（中性灰）
- 实测：均值 +28 → 显示 **156**（偏亮）

**这就是画面整体偏亮的第一个原因。**

你们在 `OUTPUT_RANGE_FIX_DONE.md §2.2` 写的是「模型输出各通道均值 R 0.872 / G 0.536 / B 0.417，做了 `bias -= 均值` 去直流」。**去直流似乎没有完全生效，或者去的是训练集统计值、与板上实际输入不匹配。**

### 2.3 显示后的分布

| 指标 | 值 | 说明 |
|---|---|---|
| 右半 R σ | **9.9**（lift 默认开） | |
| 右半 R σ | **12.3**（lift 关闭） | show 端 lift 贡献了 24% |
| 左半原画 σ | **54–55** | 同一采集卡、同一显示通路，正常 |
| **DDR σ** | **23** | 数据本身 |
| **显示/ DDR 比** | **12.3 / 23 = 0.53** | 显示端仍压缩一半 |

**其中 lift 贡献 24%，剩余 ~40% 差距未定位到具体环节**（见 §5 诚实边界）。

## 三、最刺眼的一个数字：70.9% 面积是同一颜色

### 3.1 实测

统计右半内容区（`x=1000..1860, y=240..860`），共 133,300 个采样点：

| 版本 | 不同颜色数 | **最大单色占比** | 前 3 色合计 |
|---|---|---|---|
| **当前（v4 + 红天）** | 16,091 | **70.9%（`#989898`）** | 73.8% |
| **昨天（同固件前身 + 星空 g075）** | 4,617 | **1.4%** | 3.6% |

`#989898` = RGB(152,152,152)，**中性灰**，反推 DDR 值 = 152^128 = **24**。

**同一个显示链路，昨天的星空版本最大单色只占 1.4%，今天的红天版本占 70.9%。**

### 3.2 两种解释（我未能区分）

| 解释 | 含义 | 责任方 |
|---|---|---|
| **A. 是填充值** | 显示端 match 失败，用固定值填充 | RTL |
| **B. 是真实内容** | 模型输出 70% 面积确实同色 | **模型侧** |

**倾向于 B**，因为：
1. DDR 里读到的 R 值确实是 24 附近的一个窄分布（均值 28、σ 23 但大量集中在低位）
2. 显示端 `pixel <= image && match ? data : 0`，失败时填 **0**，显示应该是 `0^0x80 = 128`（`#808080`），**而不是 152**
3. 实测填的是 152（对应 DDR 值 24），不是 128

**所以 `#989898` 大概率是 DDR 里真实存在的值。** 但我没有直接读到「24 占 70%」的分布来证明这一点（板子在最后一次验证时掉线，见 §5）。

## 四、请模型侧检查的四个点

### 4.1 输出层去直流是否真的生效

**现象**：R 均值 +28（应有 ≈0），且 G/B 也各自偏离。

**检查**：
```python
# 导出前，用【板上实际输入】跑一遍，打印最后一层输出的逐通道统计
out = model(board_frame).detach()
for c, name in enumerate('RGB'):
    print(f"{name}: mean={out[:,c].mean():+.4f} std={out[:,c].std():.4f} "
          f"min={out[:,c].min():.4f} max={out[:,c].max():.4f}")
```

**重点**：`mean` 必须在 ±0.05 以内。如果还是 0.87/0.54/0.42，说明 `bias -= mean` 那一步没落到实际权重里，或者被后续某个操作又加回来了。

> 你们报告里写的是 R 均值 0.872，板上实测 R 仍然是偏得最多的通道（+28，而 G/B 是 +26/+12）。这个「R 偏最多」的模式**在去直流前后没有变化**，可疑。

### 4.2 逐通道的 σ 差异太大

| 通道 | σ |
|---|---|
| R | 23.0 |
| **G** | **44.9** |
| B | 26.1 |

**G 的 σ 是 R 的 2 倍、B 的 1.7 倍。**

如果三个通道用的是同一个 `s_out`，σ 应该接近。现在差这么多，说明：
- 要么逐通道的 `s_out` 标定不一致
- 要么某个通道（G）的量化参数和另两个不同

**检查**：三个输出通道是否共用一个 `s_out`？如果是，用校准集统计各自的 std，确认它们量级接近。

### 4.3 大面积同色（70.9%）

**如果确认 `#989898` 是真实内容**，那说明输出在空间上大面积恒定。

**注意这与你们 §2.2 的实验结论矛盾**：你们测 PyTorch 输出相邻差异 44.36 ≈ 原画 44.28，**空间上是正常的**。

**矛盾的可能解释**：
- 你们测的是 `weinisi.jpg` 单张图，**板上是实时摄像头画面**
- 两个输入的激活分布不同，导致输出分布不同

**建议**：用**板上实际拍到的画面**（我可以提供抓图）作为输入跑 PyTorch，再对比空间统计。

### 4.4 均值 +28 和 70.9% 同色可能是同一个病

如果输出层有残余 bias 把值推向高位，那么：
- 大部分像素落在同一个偏亮的值上（→ 70.9% 同色）
- 剩余像素的偏离方向一致（→ 均值偏正、σ 小）

**这两个现象可以同时由「输出层 bias 未清干净」解释。**
