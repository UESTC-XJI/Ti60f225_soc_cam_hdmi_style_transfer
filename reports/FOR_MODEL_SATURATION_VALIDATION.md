# 量化饱和修正的板侧验证

> 2026-10-27 深夜　板侧实测
> 对象：`red_v3`（呐喊/红调），模型侧饱和修正**前**与**后**两个版本
> 结论：**修正有效，而且效果可以量化**。修正后 DC 标定从"5 轮调不动"变成"1 轮命中"。

---

## 〇 一页结论

1. **饱和修正是对的，效果显著**：同一风格两版对照，削顶 13.6% → 2.3%，DC 收敛 5 轮失败 → 1 轮命中。
2. **饱和有一个可靠的板侧症状**：**调 DC 出现非单调振荡**（同一方向调整，实测均值忽上忽下）。看到这个就应该怀疑饱和，而不是怀疑调参方法。
3. **饱和还会压低实测 σ**：旧版 R 的实测 σ 只有 28.9，修正后是 55.6。**σ 被压缩是削顶的副产品**，不是网络输出动态范围真的小。
4. 三套 starry 已全部完成 DC 标定并固化（见 §四），撞顶都在 0.5% 以内。
5. `scream_v1` 是失败的呐喊版本（画面强烈水平条纹），**未固化**，如果需要请重新导出。

## 一 受控对照实验：同一个风格，修正前 vs 修正后

这是最有说服力的证据形式——**同一风格、同一场景、同一参考图、同一套标定流程**，唯一变量是模型侧是否做了饱和修正。

### 1.1 元数据

| | 旧版（修正前） | 新版（修正后） |
|---|---|---|
| 源 XOR | `0xc9af308a` | `0xd05876b4` |
| 固化后 XOR | `0xc9aefbc3` | `0xd0593c46` |
| shift | 37 | 38 |
| M | 559,507,872 | 950,969,034 |
| 换算率 `per = 2^shift/M` | 245.64 | 289.05 |
| 原厂 L11 bias | 102785 / 82973 / 53743 | 56735 / 54872 / 33803 |
| Q 头 | `0x001FE065`（signed, qlo −127） | `0x001FE066`（signed, qlo −127） |

### 1.2 原厂状态实测（**未做任何 DC 调整**）

| 指标 | 旧版 | 新版 | 变化 |
|---|---|---|---|
| R 均值 / σ | **+76.7** / **28.9** | **−44.4** / **55.6** | σ **×1.9** |
| G 均值 / σ | +32.1 / 45.3 | −39.0 / 42.7 | — |
| B 均值 / σ | +46.1 / 28.7 | −15.1 / 27.2 | — |
| B−R | −30.6 | +29.3 | — |
| **削顶率** | **9.1%** | **0.0%** | ✅ |

**注意 R 的两行**：旧版 R 均值更高（+76.7）但 σ 更低（28.9）。这不是"输出更平淡"，
而是**削顶把分布压扁了** —— 一旦有 9% 的像素被削在 +127 上，实测 σ 必然变小。

### 1.3 按 scream_red_q.jpg 标定 DC 的过程

参考图 `scream_red_q.jpg`：R 181.7 / G 107.8 / B 83.0，**B−R = −98.8**，σ 49.7/51.9/53.8
目标 q（= 均值 − 128）：**R +54 / G −20 / B −45**

#### 旧版（修正前）：**迭代 5 轮，仍未收敛**

| 轮次 | bias R | 实测 R 均值 | 削顶 | 备注 |
|---|---|---|---|---|
| 0（原厂） | 102785 | +76.7 | 9.1% | |
| 1 | 97209 | **+89.3** | 15.8% | **调低 bias，均值反而升高** |

## 二 这告诉我们什么：饱和的两个板侧症状

### 症状 1（最可靠）：**调 DC 出现非单调响应**

调 bias 是纯线性操作，`Δq = Δbias / per`。如果实测均值不按这个走，甚至方向相反，
**唯一可能的解释是分布尾部被裁掉，均值不再代表整体**。

**判据**：连续两次同方向调整，实测均值的变化量偏离预测超过 1.5 倍 → 怀疑饱和。

### 症状 2：**实测 σ 明显低于参考图 σ**

| | 旧版 | 新版 | 参考图 |
|---|---|---|---|
| R σ | **28.9** | **55.6** | 49.7 |

旧版 R σ 只有参考图的 58%，新版是 112%。
**σ 被压缩不是"网络输出平淡"，而是削顶的副产品** —— 削顶会把高于 +127 的部分
全部压到 +127，方差直接被吃掉。

### 这两个症状的价值

**它们可以只用板子上的三个数字判断**（`mean` / `σ` / `贴轨率`），不需要看权重、
不需要重训、不需要额外工具。以后遇到"某个风格调不动"，先看这三个数：

```
贴轨率 > 5%  且  σ / 参考图σ < 0.75  且  调 DC 非单调
   => 量化饱和，回模型侧处理，别在板侧硬调
```

## 三 为什么旧版"调不动"是必然而不是偶然

旧版 red_v3 的目标是 **R 均值 +54**，而它的 R σ 是 **55.6**（修正后的真实值）：

```
均值 +54，σ 55.6
=> 均值 + 1.3σ 就到 +127（int8 上限）
=> 数学上必然有约 9~13% 的像素削顶
=> 而削顶又压低实测均值，形成负反馈
=> 迭代永远收敛不了
```

**根因不是标定方法，是"目标均值 + 输出 σ"这个组合超出了 int8 的可用动态范围。**

新版为什么能收敛？它的 σ 依然是 55.6（没变小！），但**原厂 DC 在 −44.4**，
离 +127 有 171 级余量，所以在向目标 +54 移动的过程中**不会撞墙**：
`54 + 55.6 = 109.6 < 127` ✓

**关键认识**：饱和修正不是"把 σ 压小"，而是**把 DC 挪回量程中间，让 σ 有地方展开**。
SD 值几乎没变（55.6 vs 55.6），变的是可用的头部余量。

## 五 还需要模型侧处理的

### 5.1 R/G 的动态范围仍低于参考图（三套 starry 共有）

| 通道 | 实测 σ | 参考图 σ | 比值 |
|---|---|---|---|
| R | 34.0（v8，最好的一套） | 56.9（鲜艳） | 0.60 |
| G | 37.7 | 58.6 | 0.64 |
| B | 61.9 | 62.6 | **0.99** ✓ |

**B 通道正常，R/G 只有参考图的 60%。** 而三通道共用同一个 M，说明这是
**网络输出的逐通道幅度差异**，不是量化器问题。

板侧可以用逐通道 M 硬补（R/G ×2 能把 σ 提到 49/52），但代价是削顶从 0.1% 涨到 4.4%。
**建议在导出侧加大 R/G 的输出幅度**，这样量化尺度自洽，不用牺牲动态范围。

## 六 附录：板侧 DC 标定的标准流程（可复用）

```bash
# 1) 量参考图，得到目标 q
python -c "import numpy as np;from PIL import Image;a=np.asarray(Image.open('参考图').convert('RGB')).astype(float);print([a[:,:,i].mean()-128 for i in range(3)])"

# 2) 量当前输出
python tools/style_probe.py stats --rows 240

# 3) 算新 bias
#    Δbias = (目标q − 当前q) × 2^shift / M

# 4) 写 DDR（必须先 halt，否则静默丢失）
python -c "...halt; mww 0x06F037A0/A4/A8; resume..."

# 5) 复量，若削顶 > 5% 则期望不要一次调到位（削顶会压低测量值），需 2~3 轮
```

**地址约定**：L11 bias 在 `0x06F037A0/A4/A8`，M 在 `0x06F037E0/E8/F0`，
Q 头在 `0x06F03860`。全部是 DDR 里的权重 blob 副本，掉电/重烧即恢复原厂值。

**固化**：`python tools/freeze_dc.py <风格> <bR> <bG> <bB> --ref ... --ref-mean ... --meas ...`
生成 `weights/<风格>_dc/`（header + blob + README），可用
`bash tools/build_firmware.sh weights/<风格>_dc/rowpipe_weights.h` 构建。

## 七 诚实边界

1. **σ 与参考图的对比不是严格意义的等价性检验**。风格化的输出本该与风格图不同，
   我们只对齐 DC（一阶统计量），σ 只作为"有没有被削顶吃掉"的健康指标。
2. **DC 是"每个风格 × 每个场景"的组合**，不是一次标定永久有效。今晚所有数据都在
   同一个静态场景（仪器架）下取得。换场景需要重标。
3. **旧版 red_v3 的"真实 σ 55.6"是修正后同风格测得的**，不是旧版自己测得的
   （旧版被削顶，测不准）。这个推断成立的前提是两版权重内容相近，仅量化方式不同。
4. **削顶率 2.3% 仍有影响**，只是不再破坏 DC 收敛。要完全消除需要把 σ 压到
   ±127/3σ 以内，那会牺牲对比度。
