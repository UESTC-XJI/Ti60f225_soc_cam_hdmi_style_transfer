# 笔触与画质分析报告

> 2026-10-28 · 板侧实测 + 离线分析
> 结论先行：**笔触画不出来的根因是感受野只有 73 输入像素（11.4% 画宽），
> 而参考图的笔触尺度是 25~50% 画宽。这是架构属性，改硬件改不动，应交给模型侧。**

---

## 一 一页结论

| 问题 | 判定 | 依据 |
|---|---|---|
| 风格迁移在工作吗？ | **在工作，且可观测量化** | Gram 风格损失比未风格化源帧好 **8.0 倍** |
| 笔触像参考图吗？ | **不像，差一个数量级** | 输出特征尺度 **2 px** vs 参考 **25~50% 画宽** |
| 显示端放大是瓶颈吗？ | **不是** | 换最近邻/双线性/双三次/Lanczos，尺度只在 2~3 px 之间变 |
| 输出分辨率（320×240）是瓶颈吗？ | **不是** | 320 宽的奈奎斯特完全够画 80 px 的结构 |
| 量化是瓶颈吗？ | **大概率不是**（子智能体复核中） | 量化误差只增加细粒度噪声，不会消除大尺度能量 |
| **真正的瓶颈** | **感受野 73 px** | 网络看不到 160 px 范围，无法让大区域连贯成一个笔触 |

**一句话**：网络在做"纹理统计意义上的风格化"，不是"笔触级的风格复现"。
像素级纹理是有的、甚至过量（颗粒感），但缺的是**大尺度的连贯结构**。

## 三 证据一：尺度谱 —— 决定性证据

把画面做 FFT，按波数统计能量分布。波数 k 对应周期 = 画宽/k，
所以 **波数越小 = 结构越大**。

| 尺度（占画宽） | 波数 | 我们的输出 | 参考图 | 差距 |
|---|---|---|---|---|
| ≥ 50% | ≤2 | 8.3% | 10.5% | −2 |
| ≥ 25% | ≤4 | **38.3%** | **88.5%** | **−50** |
| ≥ 12.5% | ≤8 | 25.2% | 96.7% | −71 |
| ≥ 6.2% | ≤16 | 52.7% | 98.8% | −46 |
| ≥ 3.1% | ≤32 | 84.9% | 99.5% | −15 |
| ≥ 1.6% | ≤64 | **93.9%** | 99.9% | −6 |

**读法**：

- 参考图 **88.5% 的能量在 ≥25% 画宽的尺度**——Starry Night 的大旋涡是占据画面
  四分之一到一半的结构
- 我们只有 **38.3%** 在那里，剩下 62% 全部堆在细节尺度
- ⇒ **我们的输出是"结构 + 大量高频颗粒"，参考图是"大尺度结构 + 少量细节"**

**这就是"颗粒感"的量化来源。**

### 单点对照

| 尺度 | 我们的能量 | 参考图能量 | 倍数 |
|---|---|---|---|
| 1/8 画宽（12.5%） | 0.0277 | 0.0066 | **我们多 4.2 倍** |
| 1/16 画宽（6.2%） | 0.0182 | 0.0009 | **我们多 20 倍** |
| 1/32 画宽（3.1%） | 0.0052 | 0.0002 | **我们多 26 倍** |

**我们在中细尺度上的能量是参考图的 4~26 倍。** 不是"细节不够"，是"细节过量、
大尺度不足"。

## 四 证据二：显示端放大不是瓶颈

结果帧在 DDR 里是 320×240（A-4 之后 L11 只在 320×240 上算），
显示端用**最近邻 2×** 放大到 640×480。怀疑"块状感"来自这里。

用真实板端帧离线模拟四种放大：

| 放大方式 | 高频能量 | 特征尺度 | 说明 |
|---|---|---|---|
| 原 320×240 | 40.03 | 1 px | |
| **最近邻（现状）** | 19.98 | **2 px** | 每个源像素变 2×2 同色块 |
| 双线性 | 13.16 | 3 px | |
| 双三次 | 17.70 | 3 px | |
| Lanczos | 19.56 | 2 px | |

**四种插值把特征尺度从 2 px 挪到 3 px，相差仅 1 像素。** 而目标尺度是
160~320 px（25~50% 画宽）。

⇒ **显示端换算法的收益可以忽略，不值得动。**

（补充说明：双线性还会降低高频能量 34%，即"变糊"，是纯损失。）

## 五 证据三：时间不稳定性（独立问题）

相邻两帧的对比（同一静态场景）：

| 指标 | 源帧 | 风格输出 | 倍数 |
|---|---|---|---|
| 逐像素时间 PSNR | **31.47 dB** | **17.75 dB** | 差 14 dB |
| 高频分量 σ | **7.70** | **29.07** | **3.8×** |
| 高频分量时间 PSNR | 33.08 dB | 10.19 dB | — |
| 低频分量时间 PSNR | 36.88 dB | 18.77 dB | — |
| **16×16 块时间 PSNR** | 45.37 dB | **33.32 dB ✓** | 结构稳定 |

**读法**：
- 摄像头很干净（源帧 31.47 dB，高频 σ 只有 4.09）
- 网络把高频能量**放大了 16 倍**，而且这份高频**逐帧随机重排**
- 但**结构是稳的**（16×16 块 33.32 dB）⇒ 是"轮廓清晰、表面在沸腾"，不是"画面在跳"

**这是 CNN 风格迁移没有时序约束的固有问题**，论文里通常靠 temporal loss 解决。

## 六 证据四：风格迁移确实在工作

用**训练时同一套损失函数**（`demo/ml/style_transfer/train.py:13-29` 的
`Features` + `gram`）对板端输出打分：

| 被测对象 | style loss | 相对基线 |
|---|---|---|
| 参考图自己（理论 0） | 0.000000 | — |
| **源帧（未风格化，基线）** | **0.000528** | 1.0× |
| **板端输出** | **0.000254** | **↓2.1×** |
| 交叉验证：输出 vs 墨风格参考 | 0.000315 | **仅 1.24× 更差 ⇒ 判别力弱** |

逐层（VGG16 特征）：

| 特征层 | 源帧 | 板端输出 | 改善 |
|---|---|---|---|
| relu1_2（细纹理） | 0.000063 | 0.000075 | ≈持平 |
| **relu2_2（中频）** | 0.001264 | 0.000104 | **12×** |
| **relu3_3** | 0.000606 | 0.000062 | **10×** |
| relu4_3（高层语义） | 0.000002 | 0.000001 | — |

**两个结论**：
1. **风格方向对了，但强度偏弱**（2.1 倍改善）；**判别力只有 1.24×** ⇒ 离目标风格还不够远
2. **改善集中在中频（relu2_2/relu3_3），细纹理（relu1_2）几乎没动**

第 2 点与尺度谱一致：网络补的是中频纹理，大尺度结构没补上。

## 七 根因：感受野 73 px

### 部署拓扑与感受野递推

| 层 | ci→cout | 输出 | 操作 | 感受野（输入 px） |
|---|---|---|---|---|
| L0 | 3→4 | 640×480 | 3×3 | 3 |
| L1 | 4→8 | 320×240 | 3×3 stride2 | 5 |
| L2 | 8→8 | 160×120 | 3×3 stride2 | 9 |
| L3 | 8→8 | 160×120 | 3×3 | 17 |
| L4 | 8→8 | 160×120 | 3×3 + 残差 | 25 |
| L5 | 8→8 | 160×120 | 3×3 | 33 |
| L6 | 8→8 | 160×120 | 3×3 + 残差 | 41 |
| L7 | 8→8 | 160×120 | 3×3 | 49 |
| L8 | 8→8 | 160×120 | 3×3 + 残差 | 57 |
| L9 | 8→8 | 160×120 | 3×3 | 65 |
| L10 | 8→4 | 320×240 | 3×3 + up2 | 69 |
| L11 | 4→3 | 320×240 | 3×3 | **73** |

**感受野 73 输入像素 = 640 宽画面的 11.4%。**

> ⚠ 口径说明：按**输入跳跃**递推（L1 只 +2，L2 起才 +8）；L10 的 `up×2` 是最近邻，
> 3×3 落在 2× 网格上只看到 2 个原始像素，增量 4 而非 8。
> 简化口径（忽略上采样）会给 81，本报告采用 **73**。

### 致命矛盾

```
参考图笔触尺度 = 25~50% 画宽 = 160~320 px（640 宽）
我们的感受野  = 73 px
```

**网络看不到 160 px 的范围，就不可能让那么大区域"连贯成一个笔触"。**
它只能在 73 px 的窗口里各自为政地填纹理——正是我们看到的颗粒。

### 为什么不能靠加层解决

每层 3×3 在 160×120 上贡献 +2 特征像素 = **+8 输入像素**。

```
73 → 160 px 需要再 +11 层
算力从 18 ms 涨到 ~34 ms ⇒ 帧时 26.5 → 42 ms ⇒ 帧率 31 → 20 fps
```

**破坏 30 fps 硬指标 ⇒ 不可行。**

## 八 已排除的改进方向

| 方向 | 为什么排除 |
|---|---|
| **显示端换双线性/双三次** | 尺度只从 2→3 px，离目标差一个数量级；且双线性降高频 34% 是纯损失 |
| **L11 回 640×480 全分辨率** | 只 +82 XLR，但 **+4.66 ms ⇒ 31 fps 掉到 27 fps**；且不解决感受野 |
| **加层数扩大感受野** | 算力翻倍，破坏 30 fps |
| **减少下采样** | 方向相反（会缩小感受野） |
| **降低 VTS 提帧率** | 当前已 31 fps 达标；压 VTS 会丢帧（违反要求"不丢帧"）且曝光上限等比下降 |
| **撤 profiler 腾面积** | 已实测：构建全绿、时序全正、面积更低，但**板子起不来**（固件 PC=0） |

## 九 可行动方向

### 9.1 首选：模型侧引入膨胀卷积（dilation）

**机制**：3×3 卷积加 dilation d 后，覆盖范围变成 (2d+1)×(2d+1)，**算力不变**。

| dilation | 覆盖 | 每层贡献（输入 px） | 12 层累计感受野 |
|---|---|---|---|
| 1（现状） | 3×3 | 8 | **73** |
| 2 | 5×5 | 16 | **~153** ✓ |
| 3 | 7×7 | 24 | **~233** ✓ |

**dilation=2 就能把感受野提到 153 px（24% 画宽），正好进入参考图的笔触尺度区间。**

**前提**：
1. **必须重训**（权重按 dilation 重新学）
2. **硬件需支持 dilation 寻址**：现在的 12-tap 阵列取相邻行/列，
   dilation=d 要取第 d 行第 d 列。**改动集中在 `rowpipe_layer` 的行缓冲取址**
   （`lb` 的读指针偏移），评估为**可控**，但会碰最紧的 vid 域
3. 面积增量估计：需要额外的行缓冲深度（存 d 行而非 1 行）
   —— **少于 dilation=2 时需要 3 行缓冲，实际只用 1 行 + 间隔，可能零增量**

### 9.2 次选：加宽通道（8 → 16）

**机制**：8 通道是极窄的纹理词汇量。加到 16 能显著丰富可表达纹理。

**代价**：
- 面积：MAC 阵列与 requant 都要翻倍。CI/CO 从 16 降到 8 曾省下 **XLR −491、RAM −42**，
  加回去等于吐回这部分，而当前余量只有 629
- **必须重训**

**但注意**：加宽通道**不扩大感受野**，所以对"笔触尺度"帮助有限，
主要改善"纹理丰富度"而非"结构连贯性"。

### 9.3 加时序约束（解决闪烁）

若模型侧重训，建议同时加 temporal loss（相邻帧特征一致性），
解决第五节测到的"逐帧随机重排"（高频时间 PSNR 10.19 dB）。

### 9.4 硬件侧可配合的小改动

| 改动 | 作用 | 面积 |
|---|---|---|
| dilation 寻址参数化 | 支持模型侧的膨胀卷积 | 待评估（可能 0） |
| 显示端保持最近邻 | **不做改动**（已证明无收益） | 0 |

## 十 给模型侧的建议（可直接转发）

> **问题**：板端输出缺少大尺度笔触。尺度谱显示参考图 88.5% 能量在 ≥25% 画宽，
> 我们只有 38.3%；中细尺度能量反而是参考图的 4~26 倍（颗粒感）。
>
> **根因**：部署网络感受野仅 **73 输入像素 = 11.4% 画宽**，
> 而参考图笔触尺度是 25~50% 画宽。网络看不到足够大的范围，无法产生连贯笔触。
>
> **建议**：
> 1. 训练时引入**膨胀卷积**（dilation=2 可把感受野提到 ~153 px，算力不变）
> 2. 同时加**时序一致性损失**，解决逐帧纹理重排（实测高频时间 PSNR 仅 10.19 dB）
> 3. 如可能，通道数 8→12/16 改善纹理丰富度（但这条不是主要矛盾）
>
> **硬件侧待配合**：dilation 寻址（取第 d 行而非相邻行），改动量小，可等模型侧定架构后再评估。
>
> **注意约束**：XLR 余量仅 629（98.97%），RAM 余量 54 块；
> **任何面积增加都要先做对照构建**——已发生过"纯删除 418 XLR 导致板子无法启动"的事故。

## 十一 方法可复现

### 尺度谱

```python
g = 灰度图 (resize 256×256)
g -= g.mean()
F = abs(fftshift(fft2(g)))**2
r = 半径（整数）
prof = bincount(r, F) / bincount(r)     # 按波数的能量
prof /= prof.sum()                       # 归一化
# 波数 k 对应周期 = 画宽/k，k 越小结构越大
```

### 放大方式对比

```python
im = Image.fromarray(rgb_320x240)
for m in (Image.NEAREST, Image.BILINEAR, Image.BICUBIC, Image.LANCZOS):
    up = im.resize((640,480), m)
    # 特征尺度 = 自相关半高全宽
```

### 风格损失

```bash
/c/Users/36040/.conda/envs/pytorch/python.exe tools/style_loss_metric.py \
    --ddr _m/d1.bin --w 320 --h 240 --ref <风格图>
```

工具复刻 `train.py:13-29` 的 `Features`（VGG16 features[:23]，取 3/8/15/22 层）
与 `gram`（`z@z.T/(c·h·w)`），所以数字与训练日志同量纲。

### 时间稳定性

```bash
python tools/style_metrics.py --a frame1.bin --b frame2.bin --w 320 --h 240
```
