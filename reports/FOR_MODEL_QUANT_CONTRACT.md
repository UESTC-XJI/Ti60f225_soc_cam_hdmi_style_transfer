## 一、硬件量化契约（唯一权威，请以此为准）

这套契约来自参考交付包 `starry_cap8_20261024/rtl/INTERFACE.md §8` + `network/spec.json` + `ref_full_model.py`，三者互证。工作区里的 `blob_export.py` 与它**语义不等价**（项目自己已判定，见 `INK_EXPORT_ROOT_CAUSE.md`），请不要以那个为准。

### 1.1 blob 布局（903 beat / 14,448 B / 3,612 word）

每层 = `ci×9` 个权重 beat + **4 个 bias beat** + **8 个 M/mid beat** + **1 个 Q beat** = `ci×9 + 13`。
12 层求和 = 903 beat，与 `wbase_of` 偏移表逐项吻合。

| 段 | 内容 |
|---|---|
| 权重 beat | 每 beat 16 B = 16 个输出通道各 1 个 int8 权重（一 beat 对应一个 `(cin, ky, kx)`） |
| bias beat | 每 beat 4 个 int32（通道 4 个一组） |
| M/mid beat | 每 beat = `M(c0), mid(c0), M(c1), mid(c1)` |
| Q beat | word0：`[5:0]=shift`、`[13:6]=qlo`、`[21:14]=qhi` |

### 1.2 每层的计算（`requant.v`）

```
acc[c] = Σ t·W + b'[c]                     # t 是 u8 输入（该层 xorin=1 时先做 t^0x80）
q[c]   = clamp( RHE(acc[c] · M[c], shift), qlo, qhi )
字节    = q[c] 的补码低 8 位
```

- **`RHE` = round-half-to-even（四舍六入五成双）**，不是四舍五入。用 `(x + 2^(s-1)) >> s` 会和 PyTorch 系统性不符。
- **`b'[c] = b0[c] + 128·Σw[c]`**，其中 `Σw[c]` 是该输出通道全部 `ci×9` 个 int8 权重之和。这个修正项只对"输入是无符号层"的那一层存在（`xorin=1`）。

### 1.3 ⚠ 最关键的一条：**`qlo` 同时是"输出下界"和"ReLU 使能"**

```verilog
// requant.v:114
ar = (qlo_r < 0) ? a : ((a > 0) ? a : 0);    // qlo<0 → 不 ReLU；qlo>=0 → ReLU
```

**硬件没有独立的 ReLU 开关。** `qlo>=0` 就等于声明"这一层带 ReLU"。

- 对 **11 个中间层**：没问题（`qlo=0` 且确实是 ReLU 层，`clamp(relu(x),0,255) ≡ clamp(x·M,0,255)`）。
- 对 **末层**：**这是致命的**。末层想表达"零中心的有符号输出"，但 `qlo=0` 会让它被 ReLU。

### 1.4 显示端

```
显示值 = DDR 字节 ^ 0x80 = q + 128      # q 按补码解释
```

所以 **DDR 字节必须逐位等于模型的有符号码 q**。若写成 offset-binary（0=黑），显示就会整幅 +128。

## 二、真凶：两条错误叠在一起

```
① 末层 Q beat = (qlo=0, qhi=255)     →  RTL 对末层施加 ReLU  →  负半轴全变 0  →  56% 像素同值
② 模型按 offset-binary 语义导出      →  显示端却做 +128       →  整幅抬亮
```

实测对账（redsky_v4，改动前）：

| 量 | 值 |
|---|---|
| L11 每通道 Σw（36 个 int8 累加） | 699 / 652 / 370 |
| `b0 = bias − 128·Σw` | −25777 / −23717 / −12309 |
| `m = M/2^37` | 4.369327e-3 |
| 末层输出 q（offset 域） | 30 … 68，mean **50.8** |
| 显示 = q + 128（预测） | 158 … 196，mean **178.8** |
| 板上实测右半 | 160 … 192，mean **179** ✅ 逐区间吻合 |

## 三、板上现状（我们改到哪一步了）

我们在板上把 L11 改成**有符号输出**并重标增益/偏置（纯权重侧，未改 RTL）：

| 配置 | 亮度 mean | σ | 与原画相关 r | 贴轨 | `#989898` 平坦 |
|---|---|---|---|---|---|
| 改动前 | 166.2 | 24.2 | +0.845 | 3.4% | **36.6%** |
| **改动后（当前板上）** | 97.9 | **16.7** | +0.527 | 0% | **0.0%** |
| 原画（左半参照） | 130 | **70.1** | — | — | — |

**好消息**：平坦区彻底消失，画面结构完整、可辨认。
**坏消息**：σ 只有 16.7，是原画的 1/4；三通道均值 75/100/119（蓝偏）；高对比边缘有彩色条纹。

**我们已经把 RTL 的能力用尽了**：再加大缩放（`shift` 37/38）会让输出撞到 ±127 饱和，σ 反而塌到 4.6，画面变成纯灰。这说明**数据本身的动态范围就窄**，不是显示链在压缩。

## 四、请你们做的三件事

### 4.1 末层按"有符号零中心"导出

| 项 | 现在 | 改成 |
|---|---|---|
| 末层 Q beat `qlo` | 0 | **129**（= 有符号 −127） |
| 末层 Q beat `qhi` | 255 | **127** |
| `s_out` | `1/255`（对应 offset-binary） | 按**有符号区间**重算：`s_out = (p99.5 − p0.5)/255` |
| `shift` | 37 | **38**（见 4.2；只改 `quant[5:0]`，`M` 字段不必重算） |
| `bias` | 含 `128·Σw` | 继续保持（这个是对的），但**不要引入 −128 的额外偏移** |

> 注意：`qlo` 用 **129（−127）而不是 128**。对称区间 `[-127,127]` 是导出器与 ink 变体一贯用的值，`-128` 会让符号扩展在极端值上少一个码。

### 4.2 输出量程要铺满——目标 σ ≥ 45

判据只有一条：**conv 项要在 8 位量程内铺满**。

```
用一帧真实输入跑 RTL 算术，末层 acc 跨度实测 ≈ 105,286
要求 m · 105,286 ≈ 255  ⇒  m ≈ 2.42e-3  ⇒  shift ≈ 37.9
⇒ 取 shift = 38（conv 满幅 230 LSB，利用率 90%）或 39（115 LSB，45%）
⇒ 当前的 shift = 37 时 conv 满幅 460 LSB，超量程 1.8 倍，必然大面积贴轨
```

这与 `MODEL_OUTPUT_RANGE_FIX.md §6` 的验收口径一致（要求 σ ≥ 45）。

**最干净的做法**：按校准集重算 `s_out`（取实际输出的 p0.5–p99.5），而不是在 blob 上凑 shift。

### 4.3 去掉逐通道直流偏置

现在三通道均值分别是 75 / 100 / 119（差 44 级），画面偏蓝。请保证**末层输出三通道的均值相等**（零中心）。若风格本身需要偏色，请让它在**训练时体现为像素级色偏**，而不是三通道 DC —— 后者会被显示端的 +128 和 lift 放大成整体偏色。

### 4.4 中间层不用动

11 个中间层保持 `qlo=0 / qhi=255`（即 ReLU 层）**是对的**，与 `spec.json` 的 `activation_signed=[F,F,F,F,F,T,F,T,F,T,F,F]` 一致，描述符的 `xorin` 也与之一一对应。**请不要动它们。**

## 五、验收方法

### 5.1 你们（离线，自测）

用 `ref_full_model.py` 跑一帧校准图，检查末层输出的四项：

| 指标 | 期望 |
|---|---|
| 三通道 mean | 相等，且 ≈ 0（有符号域） |
| σ | **≥ 45** |
| p0.5 / p99.5 | 接近 −127 / +127（量程用满） |
| clamp 占比 | < 1% |

### 5.2 我们（板上，10 分钟）

```
# 1) 停机 → dump 结果帧
dump_image "out.bin" 0x05800000 0x12C000
# 2) 按有符号读，算 r(q+128, 左半原画) 与 σ
```

| 结果 | 判定 |
|---|---|
| r > 0.7 且 σ ≥ 60 | 通过 |
| r > 0.7 但 σ < 30 | 量程没铺满，回到 4.2 |
| r < 0 | 符号域仍然不对，回到 4.1 |

> ⚠ 注意：`0x05800000` 只是 slot 0，风格帧会在 6 个 slot（步长 0x140000）之间轮转。要么先读 APB `0x48` 定位，要么 6 个 slot 全 dump 再挑。

## 六、附：硬件成本函数（如果你们要改网络结构）

这条对"加深度/加宽度"的决策影响很大：

```
每帧算力拍 ≈ Σ_layers  (out_px_l / 16) × (ci_l × 9 + 16)
```

| 维度 | 成本 | 结论 |
|---|---|---|
| 分辨率 | **平方** | 640×480 加一层 = 11.4 ms；160×120 加一层 = 0.71 ms（差 16 倍） |
| `ci` | **线性**（×9） | ci 翻倍 = 该层算力翻倍 |
| `cout` | **免费**（≤8 时） | MAC 阵列是 16 像素 × 8 通道全并行，cout 从 4 加到 8 不花时间 |

**⇒ 理想形态是"窄输入、宽输出、深在低分辨率"**。而当前 L0(3→4)、L10(8→4)、L11(4→3) 都是"宽进窄出"，正好反了；L10 一个层吃掉全网 30% 的 MAC，且它只是把 8 通道上采样到 4 通道。

若你们要重排结构，把重卷积搬到低分辨率、末尾统一上采样，算力可从 33 ms 降到 19 ms，省出的预算能换"深 2~3 倍"的网络。
