从行缓存到DDR请求与返回

对应 Ti60f225_soc_cam_hdmi_style_demo_merged 活动RTL。23层共享计算引擎；640×480作为逐层表的几何示例。此页不改RTL、固件或bitstream。

实线框图表示源码连接/逻辑关系；时间轴是明确假设的教学模型，不是ILA波形、实测DDR利用率或FPS预测。当前文件可能包含发布后增加的统计端口，以文末源码哈希为准，不自动等同已烧录bit。

01 / 一句话理解

不是23层硬件级联

style_network读取一条层描述，装载所需行，驱动同一套row_core。每层的完整输出写DDR，下一层再从DDR读取。

片上只保留工作集

3个输入行bank、skip行、窗口patch和权重/BN RAM；中间整张feature map不常驻片上。

预取不等于更多DDR并发

把下一行读提前到当前行计算期间。内层读桥仍一次只持有一个读burst；CNN读和显示读不能同时占有这个读通路。

02 / CNN内部数据流

青色：数据搬运；绿色：片上计算；紫色：存储；黄色：调度。图中箭头表示依赖/方向，不表示各级无条件每拍吞吐。

按一行输出展开
  1. DESC/SETUP读取层参数，清空该层行映射。
  2. MAP检查kernel所需的行；命中cache_y则复用，越界用0，缺失时发起src + physical_y × input_pitch的整行读取。
  3. 残差层先读skipaddr + y × output_pitch到skip存储，等SKIPWAIT完成。
  4. RUN同时启动行计算与行写DMA；输出经wr_ready反压，DDR写不动会停住计算流水。
  5. WAITROW等待core_done、wr_done以及存在时的预取rd_done全部满足；写完成含B响应。随后进入下一行，最后一行后进入下一层。

row_core用8个输出lane，每lane 12个INT8乘法项；输入reduction和输出channel按组复用。BN定点仿射、移位、ReLU以及可选残差加法后拼成像素。权重正常推理从片上系数RAM读取，不为每个MAC单独发DDR权重读。

03 / 完整DDR路径：不要漏掉两级桥

读请求 AR → R

row DMA发ARADDR/ARLEN，经style_axi_cdc进入100MHz域。内层在CNN/显示之间选owner，外层在视频/真正CPU之间选owner。RDATA/RRESP/RLAST沿保存的owner反向返回。

写请求 AW → W → B

网络结果与中间特征由CNN写端产生；摄像头由frame_store写端产生。AW锁定owner，W直到WLAST，B完成后释放；读写状态机相互独立，但物理DDR仍共享资源。

Lite没有移除CNN CDC

Lite移除的是Sapphire内部专用DDR时钟CDC。CNN 148.5MHz与AXI 100MHz之间仍有style_axi_cdc；显示还有AXI域到像素域的FIFO。
仲裁、突发和背压的关键限制
  • AXI数据128bit，每beat 16byte。行DMA使用INCR，单burst最多32beat（512byte），不跨4KiB边界；ARLEN/AWLEN是beat数减1。
  • 读DMA按AR → R_DATA → 行内下一burst循环；写DMA按AW → W → B → 下一burst循环。不是一整行只发一次请求，也不是多路outstanding行读。
  • 每个共享桥最多一个读burst及一个写burst outstanding，二者可并行。已接受的burst不会因显示urgent中途抢断。
  • 内层ADAPTIVE_READ默认启用：显示urgent可越过公平限制，并可预留空闲读通路；urgent即使暂时无显示AR也可能阻止CNN获准。非urgent时采用带连续显示限制的公平策略。
  • 外层保持原CPU/视频策略，内层cpu_*命名实际连接CNN，不要误判成CPU绕过了内层。
  • rvalid && rready才接受beat；wr_valid && wr_ready才接受计算像素。AR等待、R返回间隙、写响应等待和输出背压是不同原因。
  • RGB DDR格式XBGR8888，每像素4byte；内部RGB以异或0x80转换为有符号INT8，写出时反向转换。特征为紧凑NHWC INT8，不是每个像素固定192bit写DDR。

05 / 安全预取到底提前了什么

!kernel3 && !residual && !stride2 && !up2 && y+1<oh && !rd_busy

只有普通1×1非残差、不缩放层满足结构条件，且尚有下一行、读DMA空闲时，RUN才发起预取。当前中心行bank保持只读，把下一行写到另一个现有bank（中心bank为0选1，否则选0）；不新增一套行RAM。3×3、残差、下采样、上采样均不走这条预取路径。

出错及完成语义预取与当前计算、结果写入共同进行；WAITROW要求三者终止后才继续，错误会在排空后报告。计数器stat_overlap_cycles实际计的是busy && rd_valid && core_busy的周期，不代表所有读事务在途周期，也不是节省的计算周期。

06 / 同一时间轴看“算”和“读”

下面采用假设单位：两行输入、每行8单位计算，显示读窗口固定为[3,5)与[11,13)。一个逻辑行可被多个完整burst分段；方块边界才可换owner，不代表抢断burst。未画CPU、抓帧写、结果写、刷新及读写turnaround，因此不能用于性能估算。

下一行在当前计算后才读取；片上算y时，DDR可以服务显示，也可能空闲。

算y期间读y+1，显示窗口仍相同；下一行输入提前就绪。CNN读与显示读互斥，但二者都可以与片上计算重叠。悬停方块可看区间。

07 / 如何理解当前约83ms

用户报告的MS≈83是任务耗时观测，不是本页测量。只靠它无法判定MAC或DDR谁是主瓶颈。stat_read_cycles只覆盖READWAIT/SKIPWAIT；stat_compute_cycles按core_busy计数，包含写出背压。预取读、计算与显示可重叠，不能把所有计数直接相加当成精确帧拆分。

必须用相同部署bit/ELF的连续MONET、DDR100M、VIDEO日志，或增加统一时钟事件trace，才能画真实请求时间线。ERR=0和DISP=60也不能代替UF/DUF无增长的证据。
