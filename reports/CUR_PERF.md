## 三、⭐ 已全部证伪的优化（实板实测，不可再试）

| # | 方向 | 实测结果 |
|---|---|---|
| **1** | **burst 加长（240/256 beat）** | **MS 84（更差）+ UF ×16,000**；DDR 接受长 burst（ERR=0）但长 burst 垄断读通道饿死显示 |
| **2** | **UOF=0（取消 urgent override）** | **死锁**（AR=100%, RB=0, DRB=0）—— `RESERVE_URGENT_READ` 与 `streak` 交互导致双方永久等待 |
| **3** | **PAD_PITCH 4 KiB 对齐** | 依赖长 burst，随 #1 一并失败 |
| **4** | **prefetch 扩 3×3 层** | 仿真零收益 |
| **5** | **层间气泡（11 ms）** | 实测固定开销只 **0.3–0.7%**；那 11 ms 是 **DDR 写等待**，随 DDR 延迟线性增长 |
| **6** | **加 MAC 阵列（96→192）** | DSP 需 224 > 160，**不可行** |
| **7** | **1×1 层用满 taps** | **前提错误**（taps 本就对应 12 输入通道） |
| **8** | **残差层优化** | 严格同分辨率下只 **−5.1%**（1.59 ms） |
| **9** | **3×3 预取（方向 A，4 bank）** | **0%**（TOTAL cycles 106,399 不变），+136 XLR，已回滚 |

## 四、`MS` 的构成（实板口径）

```
MS 79 ms（单面板）
├── RPMS 29 ms  读相位
├── CPMS 31 ms  算相位
└── 其它 ~19 ms 写等待（DDR）
```

**关键认识**：
- 三者都与**DDR 交互次数**成正比
- 算力效率 **46%**（实板+仿真双验证：204.1M MAC ÷ 31ms ÷ 148.5MHz ÷ 96）
- **降低 `MS` 的唯一有效手段是「减少计算量」**（层数/通道数/分辨率）

## 七、否决过的前提（避免重犯）

| 我曾经的错误判断 | 实际情况 |
|---|---|
| 「读侧 3.79× 重复读，可大降」 | 实际只 **1.22×**（926,880 vs 1,132,523 beat） |
| 「1×1 层浪费 11/12 taps」 | **错**：taps 本就映射 12 输入通道，利用率 43.5% |
| 「burst 加长能省 21.3%」 | **仿真对，实板更差**（仿真 DDR 模型无仲裁竞争） |
| 「UOF=0 是单参数优化」 | **它是功能前提**，关掉即死锁 |
| 「11 ms 是层间气泡」 | 实际是**写通道 DDR 等待** |
