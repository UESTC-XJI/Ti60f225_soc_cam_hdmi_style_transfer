# ⚠️ 上板验证结果：burst 240 失败并已回滚

> 日期：2026-10-21
> 结论：**`BURST_MAX=240` 在真板上导致 DDR 完全不响应，已回滚 v3**
> 预判的最高风险（DDR 控制器不支持长 burst）**被证实**

---

## 一、验证项失败（决定性证据）

### 验证组（`outflow_final2`：BM=240 + UOF=0）遥测

| 指标 | 值 | 判读 |
|---|---|---|
| **`NN`** | **0 fps** | ❌ **推理完全停止** |
| `MS` | 47 ms | 47 ms 后放弃（非正常完成） |
| `DISP` | 60 | 显示队列照常跑 |
| `RPMS` | 10 ms | 读相位异常短 |
| `CPMS` | 32 ms | |
| **`AR`** | **100%** | ❌ **CNN 一直等 ARREADY，永远等不到** |
| **`RGAP`** | **0** | ❌ 根本没开始读 |
| **`RB`** | **0** | ❌ **CNN 读 beat = 0** |
| **`DRB`** | **0** | ❌ **显示读 beat = 0** |
| **`UF`** | **1,508,675** | ❌ **欠载暴增（基线 11）** |
| `FAULT` | 4 | 不变 |

### 失败模式解读

```
AR = 100%  +  RB = 0  +  DRB = 0
  => DDR 从第一个事务就【完全没有返回】
  => 不是变慢，是完全不工作
```

**这不是"性能未改善"，而是"功能失效"。**

---

## 二、根因确认：**DDR 控制器不支持 240-beat burst**

| 预判风险 | 结果 |
|---|---|
| **DDR 控制器是否支持 240-beat** | ❌ **证伪：不支持** |
| 显示欠载 | ✅ 确实暴增（UR 由 11 → 1.5M） |

### 为什么是 AR=100%

`arlen = 239`（240 beat）送给 DDR 控制器：
- 若控制器只接受 ≤32 beat，可能**静默拒绝**（不给 ARREADY）
- 或者控制器内部状态机无法处理，卡死

**证据链**：
- `arvalid` 长期有效 + `arready` 永不返回 → `AR` 计数器 100%
- 因为没有事务完成，`RB`/`DRB` 都是 0
- 显示 FIFO 得不到数据 → `UF` 暴增

## 四、这次失败的价值

| 项 | 说明 |
|---|---|
| **排除了一个死路** | burst 240 不可用（仿真完全测不出） |
| **验证了仿真局限** | 仿真 DDR 模型接受任何 burst 长度，**无法发现此问题** |
| **证明"必须上板"** | 这是纯离线无法发现的失败 |
| **回滚机制有效** | 2 分钟内完全恢复 |

### 仿真为什么没发现

| 仿真 tb 的 DDR 模型 | 真实 DDR 控制器 |
|---|---|
| `arready` 由简单状态机给出 | 严格的 AXI 协议实现 |
| **接受任意 arlen** | **可能只支持 ≤32 或特定范围** |
| 无协议违例检查（我还专门放宽了断言） | 静默不响应 |

**⚠️ 重要教训**：那个 `arlen>31` 的断言**不是测试平台的随意假设，而是反映了真实硬件约束**。我放宽它之后仿真通过了，但真板失败了。

**→ 那个断言原本就是正确的。**
