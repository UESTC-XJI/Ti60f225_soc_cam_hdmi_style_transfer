# 层间气泡 11 ms 定位：**不是气泡，是 DDR 等待漏计**

> 日期：2026-10-21
> 方法：**iverilog 探针**（按状态 × core_busy × wr_busy 交叉分类）
> 结论：**「层间气泡」假设被证伪；11 ms 是「双方都在等握手」的 DDR 等待**

---

## 一、原假设

`MS 83 = RPMS 41(读) + CPMS 31(算) + 11(其它)`

**我此前猜测**：那 11 ms 是「23 层×层间切换开销」，消除一半可得 −6.6%（17.4 fps）。

---

## 二、实测：探针按状态交叉分类

### 探针设计（`work/ivtest/gap_probe_tb.sv`）

对每个忙周期，按 `(state, core_busy, wr_busy)` 分类：
- `RPMS` = READWAIT(4) 或 SKIPWAIT(6)
- `CPMS` = core_busy
- **`GAP`** = 既不在 READWAIT/SKIPWAIT，也 core 不忙

并细分 GAP 到：
- `WAITROW + core已完 + wr_busy` （等 write）
- **`WAITROW + 双方都不忙`** （都在等握手）
- MAP / DESC / SETUP / RUN / NEXTROW / SKIP

### 结果：GAP 随 DDR 延迟单调上升

| DDR 延迟（拍） | GAP 绝对量 | **GAP 占比** |
|---|---|---|
| 1 | 732 | **0.7%** |
| 32 | 1,059 | 1.0% |
| 128 | 2,115 | 1.7% |
| 256 | 3,523 | 2.5% |
| 512 | 8,441 | 4.8% |
| **1024** | **22,961** | **9.1%** |
| **板上** | **11 ms** | **13%** |

### ⭐ 决定性证据：GAP 里 98% 是「双方都不忙」

**RD=1024 时的 GAP 细分**：

| 项 | 周期 | 占 GAP |
|---|---|---|
| **`WAITROW + 双方都不忙`** | **22,357** | **97.4%** |
| WAITROW + core已完 + wr_busy | 166 | 0.7% |
| MAP | 256 | 1.1% |
| DESC | 23 | 0.1% |
| SETUP | 23 | 0.1% |
| RUN | 64 | 0.3% |
| NEXTROW | 64 | 0.3% |

**→ 「层间固定开销」（DESC/SETUP/MAP/NEXTROW）合计只占 0.3–0.7%，与 DDR 延迟无关。**

**→ GAP 的本质是 `WAITROW` 期间 core 和 write 都不忙、双方都在等 DDR 握手。**

## 四、11 ms 的真实性质

### 是「写通道的 DDR 等待」，与读相位同源

`WAITROW` 等待条件：
```verilog
WAITROW: if((core_finished||core_done) && (write_finished||wr_done) && ...)
```

当 **DDR 慢**时：
- `core_done` 早已完成
- 但 `wr_done` 迟迟不来（AW/W 握手慢）
- `core_busy=0`（core 已结束）→ **不计 CPMS**
- 不在 READWAIT/SKIPWAIT → **不计 RPMS**
- **→ 全部落到 GAP**

**所以 11 ms 是「core 算完了，但在等写回 DDR」的时间。**

### 为什么遥测 W（写等待）只有 3%

遥测的 `W` 是 **100 MHz 窗口的累计百分比**，覆盖所有状态；
而单次任务内的写等待集中在 `WAITROW`，比例更高。

**两者不矛盾**：`W=3%` 是全局平均，`GAP=13%` 是单任务内的集中等待。

## 五、修正后的优化结论

### 已证伪（实板）

| 方向 | 结果 |
|---|---|
| burst 加长 | MS 84（更差）+ UF ×16,000 |
| UOF=0 | 死锁 |
| PAD_PITCH | 依赖长 burst |
| prefetch 扩 3×3 | 仿真零收益 |
| **层间气泡** | **❌ 实测：只有 0.3–0.7%，无可优化** |

### 真正有效的（全部指向同一件事）

| 方向 | 依据 | 本质 |
|---|---|---|
| **单面板** | **已实测 MS 83→78（AR 36%→23%）** | 减少显示抢 DDR |
| **剪枝中间层 16ch** | 中间 18 层占 62.1% MAC | **减少 DDR 交互次数** |
| **降分辨率 480×360** | MAC −44% | 同上 |

**统一认识：**
> **`MS 83` 里读 41 + 算 31 + 写等待 11 = 全部都与「DDR 交互次数」成正比。**
> **降低 DDR 交互次数的唯一有效手段是「减少计算量」（层数/通道数/分辨率）。**
> **所有 RTL 侧的 DDR 调度优化（burst/UOF/PAD/prefetch）已全部实板证伪。**
