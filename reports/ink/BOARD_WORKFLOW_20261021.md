## 三、工作流（6 步）

### 步骤 0：环境确认（每次必做）

```bash
# JTAG URL 与串口号【每次都会变】，必须重新枚举
jtag_chain_detect.py         # 确认 URL 与器件
serial.tools.list_ports      # 确认哪个 COM 有输出
```

**本次实测**：URL `1:4/2`，串口 **COM13**

---

### 步骤 1：烧基线 bit（`outflow_v3`）

```bat
ftdi_program.py -m jtag -u "ftdi://0x0403:0x6011:1:4/2" ^
  --jtag_clock_freq 1000000 outflow_v3\ti60f225_oob.bit
```

**成功标志**：`Device ID read from JTAG: 0x10660A79` → `... finished with JTAG programming`

---

### 步骤 2：载固件（OpenOCD）

```bat
cd software\firmware\openocd
openocd.exe -f ...\ftdi_ti.cfg -f ...\debug_ti.cfg
```

然后 telnet 4444：
```
reset halt
load_image ".../soc_video_app_v3.bin" 0x1000 bin
mdw 0x1000 4            # 校验应为 30047073
reg pc 0x00001000
resume
shutdown
```

**成功标志**：`44624 bytes written` + `running`

---

### 步骤 3：读基线遥测（1.018 s 窗口）

从 **COM13** 抓 ≥20 行，记录：

| 字段 | 含义 | 基线预期 |
|---|---|---|
| `MS` | 单次推理 ms | **83** |
| `NN` | 推理 fps | **11** |
| `DISP` | 显示 fps | 60 |
| `RPMS` | 读相位 ms | **41** |
| `CPMS` | 算相位 ms | **31** |
| `AR` | CNN 等读 % | **35%** |
| `RGAP` | 读间隙 % | **19%** |
| `DRB` | 显示读 beat | **9,39x,xxx** |
| **`UF`** | **欠载累计** | **低值（记下具体数）** |
| `FAULT` | | 4 |
| `ERR`/`CSI`/`AXI` | | 0/0/0 |

**⚠️ `UF` 是本次最关键基线** —— 后面判断优化是否引入欠载。
