# 为什么所有版本（包括 official）都没有复现演示的画风？

> 日期：2026-10-15
> 问题：项目的演示效果（笔触感）在所有版本上都未复现，包括官方 checkpoint

---

## 一、结论

**你的观察是对的：official 也没有复现图块的"笔触"。**

**但原因不是色调/亮度那些聚合指标 —— 那些 official 几乎完全命中。
真正缺的是「暗块的空间排列方式」：**

| 样本 | 暗部占比 | **暗块连通分量数** | **平均块大小** |
|---|---|---|---|
| **论文图块（目标）** | 3.3% | **94** | **33.4 px** |
| **official（正确重建）** | 4.0% | **277** | **13.9 px** |
| official@756 | 4.4% | **559** | **7.6 px** |
| 论文原照片 | 16.7% | 954 | 16.7 px |
| v6 | 12.0% | 288 | 40.4 px |
| v9 | 13.5% | 320 | 41.1 px |
| v10 | 1.4% | 149 | 9.0 px |

**论文图块只有 94 个暗块，平均 33 像素 —— 大块连通的"笔触"。**
**official 有 559 个暗块，平均 7.6 像素 —— 细碎散布的颗粒。**

**聚合指标（暗部占比 3.3% vs 4.4%）几乎相同，但空间结构完全不同。**

这就是我之前被误导的原因：我一直在比**聚合统计量**，
而聚合量无法区分"几笔大笔触"和"无数小颗粒"。

**证据可视化**：[dark_clump_proof.png](../comparison/dark_clump_proof.png)
（第三行是暗部掩码：图块是连成片的红块，official 是散点）

## 一之二、我此前的一个错误结论（已修正）

我在本文档的早期版本里写过：

> official 的距目标值 0.967，而 v6/v9/v10 分别是 6.16 / 7.46 / 4.73
> **「所有版本都不像」这个判断对 official 不成立 —— official 是像的。**

**这个结论是错的**，因为那个"距离"是**聚合指标**算出来的：

| 样本 | 亮度 | dark% | 饱和 | R−B | flat% | TV |
|---|---|---|---|---|---|---|
| **论文图块** | 166.3 | 3.3% | 0.226 | +35.2 | 5.4% | 173.18 |
| **official** | 172.9 | 3.9% | 0.201 | **+35.3** | 2.0% | 181.97 |
| v6 | 158.0 | 12.0% | 0.226 | +22.0 | 21.8% | 163.90 |
| v9 | 156.6 | 13.5% | 0.174 | +20.4 | 24.7% | 162.45 |
| v10 | 170.2 | 1.4% | 0.173 | +24.7 | 24.6% | 175.72 |

**official 的聚合量确实极接近图块（暗部 3.9% vs 3.3%、暖调 +35.3 vs +35.2）。
但连通分量分析显示它的空间结构完全不同。**

**教训（与之前 Gram 的教训同类）**：
**聚合指标匹配 ≠ 图像相似。** 必须先确认指标能否区分"结构"，
再做判断。我又一次在标定之前下了结论。

## 二、我发现的自身 bug（已修正）

**我把 official 重建错了。** 这会影响与其相关的部分结论。

### 2.1 错误内容

checkpoint `style_ukiyoe.pth` 有 **117 个键**，其中包含**卷积偏置**
（`model.1.bias`、`model.10.conv_block.1.bias` 等）。

**我此前用 `conv bias=False` 构建，`strict=False` 沉默地丢掉了 24 个键。**

| 构建 | 载入 | 缺失 | 未使用 | 判定 |
|---|---|---|---|---|
| `conv_bias=False` | **93/117** | 0 | **24** | ❌ 不完整 |
| `conv_bias=True` | **117/117** | 0 | **0** | ✅ **完整载入** |

### 2.2 正确的构建

```python
norm = nn.InstanceNorm2d(c, affine=False, track_running_stats=True)
conv = nn.Conv2d(..., bias=True)
```

**依据**：
- checkpoint 的 norm 层有 `running_mean/var/num_batches_tracked` 但**无 affine 权重**
- 有卷积偏置 → CycleGAN 在 norm 为 InstanceNorm 时用 `bias=True`
  （`networks.py:570-573`）

### 2.3 影响范围（已核实）

**影响不大的部分**：验证集平均 RGB

| | 平均 RGB |
|---|---|
| 正确构建 | **(131.2, 125.0, 110.0)** |
| 我此前记录的 | (131.4, 125.3, 110.2) |
| 差异 | **−0.2 / −0.3 / −0.2 LSB** |

**→ 亮度与 R−B 基本未受影响**（差异 < 0.3 LSB）。

**→ 但 distinct / entropy / flat 受到的【影响很大】**，我在别处写「基本未受影响」
是**错的**，已在 2026-10-16 复核修正：

| 指标 @512 | 错误构建 | **正确构建** | 变化 |
|---|---|---|---|
| 平均 RGB | (131.4, 125.3, 110.2) | **(131.2, 125.0, 110.0)** | −0.2 LSB |
| distinct colours | **1095** | **1220** | **+11%** |
| colour entropy | **7.65** | **7.87** | +0.22 |
| flat share | 3.0% | **5.1%** | +2.1pp |
| dark share | 11.9% | **25.4%** | **×2.1** |

**所以「亮度几乎不变」不能推广成「各项指标几乎不变」。**
离散量（distinct、flat、dark）对偏置缺失远比连续均值敏感。

**但 dark% 变化很大**：

| 构建 | dark% @512 |
|---|---|
| 正确 | **25.4%** |
| 错误 | 11.9% |

**（注意 513 与 512 不同尺度下的 dark% 也不同：本文档第一节的 378×253 表里
official 是 3.9%–4.4%，那是小尺寸下的数值，与 512 的 25.4% 不矛盾。）**

**→ 所有涉及「暗部占比 / flat / distinct」的 official 数值需以正确重建为准。**
错误构建让 official 显得比实际更暗、更不平坦、且颜色更少。

## 三、为什么我们的模型不像、而 official 像

### 3.1 两者的差距在哪

对照 official（几乎命中）：

| 指标 | official | 图块 | v6 | v9 | v10 |
|---|---|---|---|---|---|
| **dark%** | **3.9%** | 3.3% | 12.0% | 13.5% | 1.4% |
| **flat%** | **2.0%** | 5.4% | 21.8% | 24.7% | 24.6% |
| **TV** | **181.97** | 173.18 | 163.90 | 162.45 | 175.72 |
| **R−B** | **+35.3** | +35.2 | +22.0 | +20.4 | +24.7 |
| 饱和 | **0.201** | 0.226 | 0.226 | 0.174 | 0.173 |

### 3.2 三个把我们区分开的核心量

**① 暗部占比与平坦度是一体的**

official dark 3.9% + flat 2.0%，图块 dark 3.3% + flat 5.4%。
**两者一致：画面里既有很暗的块，又几乎没有"死平"的区域。**

我们的模型两难：
- v6/v9：保留大量中间调（dark 12-13.5%），但 flat 21-25%（大片平坦）
- v10：暗部被压到 1.4%，flat 反而升到 24.6%

**说明：我们的模型既没有官方那种"集中压暗 + 高频密集"的组合。**

**② TV（局部变化总量）**

official 181.97 > 图块 173.18 > v10 175.72 > v6 163.90

**official 的局部变化比论文图块还高。** 我们始终不足。

**③ 暖调 R−B**

| | R−B |
|---|---|
| 图块 | +35.2 |
| **official** | **+35.3** ✅ |
| v6 | +22.0 |
| v9 | +20.4 |
| v10 | +24.7 |

**official 与图块几乎相同（+35.2 vs +35.3），我们差 10–15 LSB。**

## 四、根本原因

**图块的"笔触"是一种空间结构（大块连通暗区），不是聚合统计量。**

**official 的聚合量几乎命中（暗部 3.9% vs 3.3%、暖调 +35.3 vs +35.2），
但它的暗区是 559 个 7.6 像素的细碎斑点，而不是 94 个 33 像素的块。**

**为什么图块（和任何 DCGAN 型生成器）会产生大块连通暗区，
而 official 的 756px 渲染不会？**

| 因素 | 说明 |
|---|---|
| **图块是 379×253 的小图** | 大笔触在小图上仍是大块；同样的纹理在 756px 渲染后就是细碎斑点（实测 559 块 / 7.6px） |
| **图块来自 PDF 栅格化** | 缩小再放大（实测）可把各向异性从 0.75 提到 0.88，产生块状 |
| **论文配图可能经过额外处理** | 无法确认，但它是唯一能产生该结构的样本 |

**注意：** 我未能在本文中证明"PDF 加工"是唯一原因 ——
上述是**可能性排序**，不是已证实的结论。

**可以确定的是**：
- 图块的空间结构与 official 在 **756px 的原生渲染不同**
- 我们的模型（v6/v9/v10）都**没有**大块连通暗区（v6 288 块/40px，但暗部占 12%，是"阴影"不是"笔触"）

---

## 五、那么「笔触」具体是什么

从连通分量分析看，图块的特征是**大块连通的暗区**：

| 特征 | 图块 | official@756 | v6 |
|---|---|---|---|
| 暗部占比 | 3.3% | 4.4% | 12.0% |
| **暗块个数** | **94** | **559** | 288 |
| **平均块大小** | **33.4 px** | **7.6 px** | 40.4 px |
| 暖调 R−B | +35.2 | **+35.3** | +22.0 |
| flat% | 5.4% | 2.0% | 21.8% |

**v6 的平均块大小（40.4）甚至比图块（33.4）还大，但它的暗部占 12%
——那些是照片本身的阴影区，不是"笔触"。**

**所以"笔触感" = 暗部占比较低（3-4%）+ 少数几个大块连通。**


| 极少死平 | flat 5.4% |
| 高局部变化 | TV 173 |
| 暖调 | R−B +35 |
| 低饱和 | 0.226 |

**这不是"方向性笔触"（各向异性在 official 与输入间无差异：0.752 vs 0.725）。**
**而是"整体色调 + 暗块 + 高频颗粒"的组合。**

**我此前把它当作"方向性笔触"并去追各向异性，方向是错的。**

## 六、要真正复现，需要什么

**首先：这个目标值得重新评估。** 图块的"大块连通暗区"可能来自
PDF 配图的生产过程（缩小再放大），**不一定是模型应有的行为**。
在追它之前应先确认"demo 想表达的是什么"。

若确实要复现该结构：

| 方案 | 说明 | 可行性 |
|---|---|---|
| A. 加判别器（真正的 GAN） | 迫使输出进入目标域流形 | ❌ 学生仅 8,251 参数，且板上无法部署判别器 |
| B. 匹配 3D 颜色联合直方图 | 比现在的分位数更强 | ◐ 可做 |
| C. 加"暗块连通性"损失 | 直接约束连通分量大小 | ⚠️ 不可微，需近似 |
| **D. 接受现状 + 诚实定位** | 我们的模型是"轻量风格修饰" | ✅ |

**我建议 D**（附带 B 作为可选改进）：

- 我们的学生只有 **8,251 参数**（官方的 0.072%）
- 板的内部计算分辨率是 **160×120**，无法表达 33 像素的大块笔触
- **诚实的定位是"轻量浮世绘风格滤镜"，而非"复现论文效果"**

## 附：正确的官方模型构建代码

```python
import torch, torch.nn as nn

def official_generator(ck_path, ngf=64, n_blocks=9):
    """Exact reconstruction of the released style_ukiyoe.pth.

    Verified: loads 117/117 keys with 0 missing and 0 unexpected.
    Requires conv bias=True and InstanceNorm2d(affine=False,
    track_running_stats=True) - a bias=False build silently drops 24 keys.
    """
    nl = lambda c: nn.InstanceNorm2d(c, affine=False, track_running_stats=True)

    class Blk(nn.Module):
        def __init__(self, d):
            super().__init__()
            self.conv_block = nn.Sequential(
                nn.ReflectionPad2d(1), nn.Conv2d(d, d, 3), nl(d), nn.ReLU(True),
                nn.ReflectionPad2d(1), nn.Conv2d(d, d, 3), nl(d))

        def forward(self, x):
            return x + self.conv_block(x)

    m = [nn.ReflectionPad2d(3), nn.Conv2d(3, ngf, 7), nl(ngf), nn.ReLU(True),
         nn.Conv2d(ngf, ngf*2, 3, 2, 1), nl(ngf*2), nn.ReLU(True),
         nn.Conv2d(ngf*2, ngf*4, 3, 2, 1), nl(ngf*4), nn.ReLU(True)]
    m += [Blk(ngf*4) for _ in range(n_blocks)]
    m += [nn.ConvTranspose2d(ngf*4, ngf*2, 3, 2, 1, 1), nl(ngf*2), nn.ReLU(True),
          nn.ConvTranspose2d(ngf*2, ngf, 3, 2, 1, 1), nl(ngf), nn.ReLU(True),
          nn.ReflectionPad2d(3), nn.Conv2d(ngf, 3, 7), nn.Tanh()]
    net = nn.Sequential(*m)
    ck = torch.load(ck_path, map_location='cpu', weights_only=False)
    miss, unexp = net.load_state_dict(ck, strict=False)
    assert not miss and not unexp, 'incomplete load: %d missing %d unexpected' % (
        len(miss), len(unexp))
    return net.eval()
```
