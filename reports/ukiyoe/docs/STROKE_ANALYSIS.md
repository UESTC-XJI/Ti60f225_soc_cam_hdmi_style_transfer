# 笔触可达性分析：能否刻意突出笔触？

> 日期：2026-10-14
> 问题：板的 160×120 瓶颈能否表达浮世绘的笔触？能刻意强化吗？

---

## 1. 结论先行

| 问题 | 答案 |
|---|---|
| 板能显示笔触吗？ | **能**，但最小 2 显示像素，需要 ≥8 px 才有完整对比度 |
| 现有输出有笔触吗？ | **有方向性但偏弱**（各向异性 1.578，噪声是 1.001，真笔触是 2.846） |
| 能刻意突出吗？ | **能，且训练层面就能做**，不需要改 RTL |
| 代价 | 改损失函数 + 重训（约 1 小时） |

---

## 2. 输出分辨率：全 640×480（修正一个错误结论）

> **本节原本写的是「板的最细粒度是 2×2 显示像素」。这个结论是错的，已修正。**

### 2.1 我原先的推理（错误）

当时我看 `graph.json` 的层列表，看到 `dec.1` 是 1×1 卷积，就推断：
"最后一次上采样后只有 1×1 卷积，所以输出应该是 2×2 块状的"。

块平坦度指标似乎也支持这个判断（2×2 的比值 0.1275 比 4×4 的 0.1987 更小）。

### 2.2 实际测量推翻了这个结论

直接对整数网络输出做**精确的块检测**：

| 图像 | 2×2 块内最大差异 |
|---|---|
| 第 1 张 | **140** |
| 第 2 张 | **155** |
| 第 3 张 | **126** |
| 第 4 张 | **136** |

**2×2 块内有高达 155 灰阶的变化** —— 输出**不是** 2×2 块状的。

### 2.3 真正的原因：解码器在上采样之后还有 3×3 卷积

关键在于**每层的执行顺序**：

```python
# integer.py 的实际顺序
for layer in layers:
    if layer['upsample'] == 2:
        x = x.repeat(2, 0).repeat(2, 1)      # 先 nearest 2× 上采样
    x = conv(x)                               # 再卷积
```

所以：

| 层 | 实际发生的事 |
|---|---|
| dec.0 | 160×120 --nearest 2×--> 320×240 --**DWConv3×3**--> 320×240 |
| dec.1 | 320×240 --1×1--> 320×240 |
| dec.2 | 320×240 --nearest 2×--> 640×480 --**DWConv3×3**--> 640×480 |
| dec.3 | 640×480 --1×1--> 640×480 |

**`dec.0` 和 `dec.2` 是 3×3 卷积，不是 1×1**（`graph.json` 里 `kernel=3`）。
它们在**上采样之后的完整分辨率**上运行，3×3 邻域会跨越 2×2 块边界，
因此**能够合成真正 1 像素级的细节**。

我用一个数值实验确认了这点：给一个 2×2 块状输入做 3×3 卷积，
输出在同一 2×2 块内产生了 230 的差异。

### 2.4 修正后的正确表述

| 项 | 值 |
|---|---|
| **输出分辨率** | **完整 640×480**（解码器有 3×3 卷积） |
| **信息分辨率** | **160×120**（编码器降采样 4×） |

**网络能"画出"精细纹理，但只能被 160×120 的粗略信息"引导"。**

这才是真正的限制，与"输出是 2×2 块状"完全不同。

### 2.5 这个修正的影响

| 受影响的结论 | 变化 |
|---|---|
| "笔触最小宽度 2 px" | ❌ 推翻——网络可输出 1 px 级结构 |
| "320×240 的头是显示等价的" | ❌ **不成立**——全分辨率下确有可见细节 |
| 全分辨率 3×3 头的必要性 | ✅ **更强**——因为输出端确实用到了全分辨率 |

**对方案设计的影响**：若要新增"颜色头"，**必须放在全分辨率**才能与解码器的
输出分辨率匹配，不能省到 320×240。但代价相应更高（见 §6）。

## 3. 笔触宽度存活率（实测）

构造不同宽度的平行笔触，过一遍板的瓶颈（4× 平均下采样 + 4× 最近上采样）：

| 笔触宽度 | 对比度保留 | 判定 |
|---|---|---|
| 显示 4 px（1 内部 px） | **46.8%** | 严重模糊 |
| 显示 8 px（2 内部 px） | **67.8%** | 部分保留 |
| 显示 12 px（3 内部 px） | 73.0% | 部分保留 |
| **显示 16 px（4 内部 px）** | **100%** | **完整保留** |
| 显示 ≥32 px | 100% | 完整保留 |

**训练指导**：在 256×256 训练图上，笔触需要 **≥3.2 px** 才能在 640 宽的推理图上
表现为 8 显示像素。**训练 1 px 笔触是浪费。**

## 4. 现有输出的纹理特征

用**各向异性**区分"笔触"（有方向）与"噪声"（无方向）：

| 来源 | 各向异性 | 判定 |
|---|---|---|
| 白噪声 | **1.001** | 完全无方向（基准） |
| 官方 Ukiyo-e | 1.431 | 方向性弱 |
| 我们的教师 | **1.578** | **比官方更有方向性** |
| 输入照片 | 1.637 | — |
| 合成 6px 笔触 | **2.846** | 强方向性（理想笔触） |

**关键读数**：

- 我们的教师 **1.578 > 噪声 1.001** → **确实不是纯噪声**
- 但 **1.578 < 理想笔触 2.846** → **方向性弱于真正的笔触**
- 而且**比官方（1.431）还强** → 纹理本身不差

**细节量**（梯度）：

| | 梯度 |
|---|---|
| 输入 | 10.78 |
| 板上输出 | **10.63** |
| 官方 | 11.58 |

板上输出与原图**基本持平（10.63 vs 10.78）**——**没有明显增加纹理**，但也没减少。

## 5. 为什么笔触「看不出来」

综合前面的分析，有三个叠加原因：

### 5.1 色调差距掩盖了纹理（主因）

实测分解：

| | 均值 RGB | 对比度 | 细节 |
|---|---|---|---|
| 官方 | (137.5, 128.4, 113.1) | 43.26 | 11.58 |
| 我们的教师 | (104.0, 104.2, 102.5) | **56.02** | 10.36 |
| **差距** | **22.7 LSB** | **1.30×** | 0.89× |

**官方效果 = 大幅提亮 + 降低对比度**。我们的教师**几乎不提亮，反而对比度更高**。

**高对比度会压制笔触的可见性**——当画面整体对比强时，细纹理被淹没。

### 5.2 Gram 损失对亮度不敏感

`train.py:17-18` 的 VGG 特征做了均值/方差归一化：

```python
self.mean = torch.tensor([.485, .456, .406])
self.std  = torch.tensor([.229, .224, .225])
```

**所以 Gram 损失完全看不见"整体提亮"**。这解释了那个反直觉现象：

| | Gram | 像素强度 |
|---|---|---|
| 我们的教师 | **0.595（更好）** | 20.81（只有官方 59%） |
| 官方 | 0.618 | 35.39 |

### 5.3 笔触频段确实弱

径向频谱（风格差值的能量分布）：

| 频段 | 官方 | 教师 | 比值 |
|---|---|---|---|
| 0.0–0.1（色调） | 0.9750 | 0.9034 | 0.93 |
| **0.1–0.2（笔触）** | 0.0077 | **0.0172** | **2.23** |
| **0.2–0.3（瓶颈处）** | 0.0054 | **0.0103** | **1.92** |
| 0.4–0.5 | 0.0030 | 0.0110 | 3.66 |
| 0.8–0.9 | 0.0003 | 0.0089 | **30.48** |

**我们的教师在笔触频段（0.1–0.3）的能量是官方的 2 倍** —— 但其中一部分落在**瓶颈之外**。

超截止频率的能量占比：

| | 超过 r=0.25 的比例 |
|---|---|
| 官方 | **1.2%** |
| 我们的教师 | **6.9%** |

**我们的教师把 6.9% 的能量放在了板看不见的频段**——这部分被浪费了，而且可能在显示时形成杂乱的浅纹理，冲淡真正的结构。

## 6. 刻意突出笔触的三个可行手段

### 6.1 加入色调/对比度损失（最高优先，成本最低）

这是**当前最大的单项差距**（22.7 LSB），且**低频、现有网络完全能表达**：

```python
# 在 train.py 的损失里增加
# 风格参考图的均值/方差（从 8 张浮世绘预先统计）
tone_loss = (F.mse_loss(y.mean(dim=[2,3]), style_mean)
           + F.mse_loss(y.std(dim=[2,3]),  style_std))
loss = content_w*content + style_w*style + tv_w*tv + 50*tone_loss
```

**预期收益**：实测证明，给教师输出做一次全局色调匹配（+32.4/+24.0/+11.2），
平均 |Δ| 从 **29.12 → 36.68**，达到官方的 **100%**。

**副作用（正面）**：降低对比度后，笔触会**更容易被看见**（不再被整体对比淹没）。

### 6.2 低频加权：把能量拉回可表达频段

当前教师有 6.9% 的签名能量在瓶颈之外。可在风格损失里**对低频 Gram 加权**：

```python
# 对 VGG 的浅层（relu1_2 / relu2_2，对应细纹理）降权
# 对深层（relu3_3 / relu4_3，对应中尺度）加权
style = sum(w_i * F.mse_loss(gram(f), g) for i, (f, g) in enumerate(zip(yf, target)))
# 例如 weights = [0.3, 0.5, 1.5, 2.0]
```

**理由**：`features()` 返回 `[relu1_2, relu2_2, relu3_3, relu4_3]` 四层。
relu1_2 对应的空间尺度约 1–2 px，**过不了瓶颈**；relu3_3 约 8–16 px，**能完整通过**。

**预期收益**：把训练目标对准板真正能显示的尺度。

### 6.3 笔触尺度的显式约束

在训练时**保证笔触宽度 ≥3.2 px**（256 训练图）：

- 用 256×256 训练时，**不要用更小的 crop**（会更缩小笔触）
- 风格参考图的**分辨率要足够**（若参考图被缩到 256，原图的大笔触会变小）
- 可选：对风格图做轻微 **downscale-upscale**，去掉 1 px 级的细节，强制网络学中尺度

## 7. 为什么不需要改 RTL 来加笔触

| 论点 | 依据 |
|---|---|
| **输出分辨率够** | **完整 640×480**（解码器含上采样后的 3×3 卷积） |
| 现有纹理有方向性 | 各向异性 1.578 > 噪声 1.001 |
| 细节量不缺 | 板上梯度 10.63 ≈ 输入 10.78 |
| 差距在色调 | 22.7 LSB，低频，不需扩容 |
| 能量用错频段 | 6.9% 超截止，靠损失函数加权即可改善 |

**笔触问题本质是「训练目标没对准」，不是「硬件表达不了」。**

> **但要注意**：虽然输出是 640×480，**用于引导它的信息只有 160×120**（编码器降采样 4×）。
> 所以网络能画细纹理，但无法依据细尺度信息决定"这里该是什么颜色"。
> 这正是"天空无法转暖"的原因（见 `CYCLEGAN_SOURCE_NOTES.md`）。

---

## 8. 建议的执行顺序

| 步骤 | 内容 | 成本 | 预期 |
|---|---|---|---|
| **1** | 加色调/对比度损失（§6.1） | 改几行 + 重训 1h | 强度追平官方，笔触更易见 |
| **2** | 低频加权（§6.2） | 改几行 + 重训 1h | 能量拉回可表达频段 |
| **3** | 若仍不够 → 扩容 32 通道 | 改 RTL + 重训 + 重综合 | 强度 ×1.3，fps 10→7.7 |

**先做 1+2（都在训练层面），只有效果仍不足时才动 RTL。**
