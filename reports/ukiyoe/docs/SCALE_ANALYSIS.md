# 提升训练规模有用吗？—— 实测结论

> 日期：2026-10-15
> 方法：用已有 checkpoint 的收敛曲线与风格目标质量实测，不靠推测

---

## 结论速览

| 规模维度 | 有用吗 | 依据 |
|---|---|---|
| **更多步数** | ❌ **有害** | content 仍在下降，**越低越像原图** |
| **更多数据** | ❌ 不可能 | 已是官方全量（7863 文件逐字节相同） |
| **更大容量（教师）** | ◐ 有空间但非瓶颈 | 教师仅官方 12.1%，但 loss 已低于官方 |
| **更多风格参考图** | ❌ **无效** | 8 张与 400 张的目标差异 **< 0.0011** |
| **更大容量（学生）** | ◐ 受 RTL 限制 | 学生仅官方 0.072% |

**核心发现：「更多训练」会让输出更像原图 —— 正是当前的问题。**

---

## 一、更多步数：**有害**

三个版本在 2500 步时的收敛斜率（每个验证区间 content 的下降量）：

| 版本 | 最后 content | 尾部斜率（每区间） | 官方 |
|---|---|---|---|
| v6 | 1.492 | **+0.133** | 2.441 |
| v7 | 1.502 | **+0.128** | 2.441 |
| v8 | 2.903 | **+0.068** | 2.441 |

**三个版本都在持续下降（未饱和）。**

### 但这意味着什么

`content` 的定义是：

```
content = MSE( features(输出)[relu3_3], features(输入)[relu3_3] )
```

**数值越低 = 输出的 VGG 特征越接近输入。**

| 版本 | content |
|---|---|
| **官方** | **2.441** |
| v6 | **1.492** ← 比官方还低 |
| v7 | 1.502 |

**我们的 v6/v7 已经比官方更"接近原图"了，而 loss 还在往下走。**

**继续训练 → content 更低 → 输出更像原图 → 风格化更不明显。**

**这正是用户反映的问题，而更多训练会加重它。**

### 独立验证：像素级相似度

| 版本 | 归一化像素 MAE |
|---|---|
| 官方 | 0.1444（36.78/255） |
| v6 | 0.1473（37.57/255） |
| v8 | 0.1429（36.44/255） |

**改动幅度相近**，但官方是**重分配颜色**，我们**保留照片结构**（見 `TRAINING_DIRECTION.md`）。

---

## 二、更多数据：**不可能**

| 项 | 值 |
|---|---|
| 我们的数据集 | 7863 个文件，**与官方逐字节相同**（SHA256 全量校验） |
| trainA（浮世绘） | 500 |
| trainB（照片） | 5500 |

**官方 ukiyoe2photo 就是这些，没有更多。**

**官方 CycleGAN 的数据暴露量对比**（`options/train_options.py:25-26`）：

| | 迭代数 | 图像数 |
|---|---|---|
| 官方 | 200 epochs × 5500 | **约 1,100,000** |
| 我们（2500 步 × batch 4） | | **10,000** |
| 我们（8000 步 × batch 12） | | **96,000** |

**我们的数据暴露量是官方的 0.9%–8.7%。**

**但这个对比不成立**：官方是**对抗式 GAN**（4 个网络），我们是**确定性回归 + 蒸馏**。
GAN 需要极多迭代来稳定对抗训练，回归任务收敛快得多。

**证据**：我们的 content（1.492）已经**低于**官方（2.441）——说明在"结构保真"这个目标上，
我们早已超过官方，**不是训练不足**。

---

## 三、容量

| 模型 | 参数量 | 占官方 |
|---|---|---|
| 我们的 Teacher | 1,383,555 | **12.1%** |
| 我们的 Student（部署） | 8,251 | **0.072%** |
| 官方 ResNet 9-block | 11,388,675 | 100% |

**教师容量有空间**，但如§1 所示，**增加训练只会让它更像原图** —— 容量不是风格化的瓶颈。

**学生容量受 RTL 硬约束**（24 输入通道 / 32 输出通道 / RAM 256 已满）。

---

## 四、更多风格参考图：**无效**（实测）

**当前 Gram 目标只用了 8 张画（500 张里的 1.6%）。**

我本想推荐"增加风格参考图"，但**先做了实测**：

| 目标规模 | 与 8 张目标的平均差异 |
|---|---|
| 16 张 | 0.00109 |
| 32 张 | 0.00083 |
| 64 张 | 0.00100 |
| 128 张 | 0.00103 |
| **400 张** | **0.00089** |

**即使把参考图从 8 张扩到 400 张，Gram 目标的差异也只有 0.00089。**

**对比目标本身的量级**：

| 层 | 目标均值 | 目标 \|max\| |
|---|---|---|
| 0 | 0.009361 | 0.132888 |
| 1 | 0.010835 | 0.285130 |
| 2 | 0.005427 | 0.195506 |
| 3 | 0.000313 | 0.026273 |

**差异 0.00089 相对目标量级（0.005–0.011）约 8%–17%，且方向随机（不改善）。**

**结论：8 张参考图已经足够，扩到 400 张没有收益。** 这条路省了。

---

## 五、真正的问题不在规模

| 规模轴 | 状态 |
|---|---|
| 步数 | ✅ 足够（甚至过多） |
| 数据 | ✅ 已是官方全量 |
| 风格参考 | ✅ 8 张已足够（实测） |
| 教师容量 | ◐ 有余量，但非瓶颈 |
| **损失函数** | ❌ **缺颜色分布约束** ← 真问题 |

**把训练规模翻倍，只会让 content 从 1.492 进一步下降，输出更像原图。**

---

## 六、可做的规模调整（针对内容/风格平衡）

既然 content 下降是"更像原图"的原因，**v9 的方向应该是调整损失权重**，
而不是加大规模：

| 措施 | 说明 |
|---|---|
| **降低 content-weight** | 当前 1.0；降低可让风格表达更自由 |
| **提高 style-weight** | 当前 1500；但 Gram 指标有地板且已接近，空间有限（见下） |
| **提高 palette / quantile** | 直接约束颜色分布（v9 已在计划中） |

**注意 v8 的反常**：content 恶化到 2.903、flat 到 26%。

> **更正（2026-10-15）**：此处原写「v8 的 ratio 0.642 远比官方 0.849 好」——
> **该比较已撤回**。两个数字来自不同设置（目标@256/特征@640 vs 目标@512/特征@512）。
> **统一设置下：官方 0.533（正好在 Gram 地板 0.000031）、v8 0.611、v6 0.468。**
> 也就是说 **v8 的 Gram 反而比 v6 差**，且官方在这项指标上是满分。
> 详见 `GRAM_METRIC_AUDIT.md`。

**说明 v8 是"结构受损"**（content +47%、flat 26%）——
这进一步证明问题**不在训练量**，而在**损失权重的平衡**。
