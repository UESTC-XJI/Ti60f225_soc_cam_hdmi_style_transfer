# 星空（starry g075 / g085）上板实测与修复记录

> 2026-10-27　板侧
 
> 结论：**star 系列导出时用的是 offset-binary + ReLU 的那套旧约定**（和 redsky v5 修之前一样），
> 再加上它的输出动态范围本身就窄。板侧用 L11 量化头 + 逐通道 bias 重标把它救回来了：
> **σ 7.7 → 30.9，三通道 DC 归零，削顶 0%**。权重一个字节没改。

---

## 一、先纠正一个方法问题

`artifacts/soc_video_app_starry_g075.bin` 这类 bin 是**旧固件**（10-26 23:56 之前编的），直接烧会把板侧这些修复一起覆盖掉：

| 被覆盖的东西 | 后果 |
|---|---|
| 相机增益校准 400/256/414 | 打回 520/520，画面偏色 |
| AE 高光保护（A2） | `hot` 恒 0、goal 恒 128 |
| A1 性能遥测 | `DDR100M ...` 整行消失 |

**正确做法：只换权重，不换固件。**

```bash
cp <导出目录>/rowpipe_weights.h software/firmware/rowpipe_weights.h
bash tools/build_firmware.sh
```

三种换风格的方法，按速度排：

| 方法 | 耗时 | 代价 |
|---|---|---|
| **DDR 直写 blob 到 `0x06F00000`** | **~2 秒** | 无（开机自检已跑过，绕过） |
| 换 `.h` 重编固件 | ~40 秒 + 重配 bit | 会锁采集故障 |
| 烧现成 `.bin` | ~4 分钟 | 覆盖所有板侧修复 |

⚠ DDR 直写的方法：`load_image {blob.bin} 0x06F00000 bin`，14,448 B。**这是本轮最好用的工具**。

## 二、实测：三套风格同一场景对比（色卡场景，顶部 153 行）

| 变体 | σ (R/G/B) | mean (R/G/B) | 输出范围 |
|---|---|---|---|
| **redsky v5** | **60.4 / 55.8 / 43.5** | +9.2 / +4.5 / +10.7 | −127…+115 |
| starry g075 | 7.7 / 8.2 / 5.8 | +20.3 / +26.0 / +30.8 | **0…+51** |
| starry g085 | 10.3 / 10.9 / 7.7 | +27.1 / +34.6 / +41.1 | **0…+67** |

两条结论：

1. **starry 的动态范围只有 redsky 的 1/6~1/8** ⇒ 画面上就是"发灰、没层次"
2. **starry 的输出全为正**（范围从 0 起）⇒ 末层被 ReLU 削过

---

## 三、根因：两件事同时发生

### 3.1 L11 量化头是旧约定（`qlo=0` ⇒ ReLU）

两个 starry 变体的 Q 头都是 `0x003fc027`：

```
shift = 39    qlo = 0    qhi = 255      ← offset-binary，且 qlo=0 会触发 ReLU
```

和 redsky v5 修之前**一模一样**（见 `reports/FOR_MODEL_QUANT_CONTRACT.md` §1.3）。

### 3.2 导出尺度偏小

L11 的 `M = 435,501,648`（三通道相同），`m = M/2^39 = 0.000792`。
按这个尺度 conv 项只铺满量程的一小部分 ⇒ σ 只有 7 左右。

### 3.3 为什么要一起改

只改 bias 把 DC 拉到 0 是没用的 —— **ReLU 会把负的那一半削掉**：

| 配置 | σ | 范围 | 说明 |
|---|---|---|---|
| shift=39 原样 | 7.7 | 0…+51 | 全正、发灰 |
| shift=38 + bias 居中（**仍是 ReLU**） | 7.1 | 0…+55 | **σ 反而更小**：下半被夹成 0 |
| shift=38 + **有符号** + bias 居中 | **15.5** | −59…+54 | 削顶 0%，恢复正常 |
| **shift=37 + 有符号 + bias 居中** | **30.9** | −115…+117 | **削顶 0%，最终方案** |

## 四、最终修复参数（可直接落盘）

只改 DDR 里三个字 + 一个量化头，**权重不动**：

| 地址 | 字段 | 原值 | 改为 |
|---|---|---|---|
| `0x06F037A0` | L11 bias ch0 (R) | 28575 | **3278** |
| `0x06F037A4` | L11 bias ch1 (G) | 41293 | **8869** |
| `0x06F037A8` | L11 bias ch2 (B) | 53398 | **14559** |
| `0x06F03860` | Q 头 | `0x003fc027` | **`0x001fe065`** |

`0x001fe065` 的拆解：`shift=37`、`qlo=129`（= 有符号 −127）、`qhi=127`。

**实测结果**：

```
σ  30.9 / 32.5 / 23.3        （原 7.7 / 8.2 / 5.8，提升 4 倍）
mean +0.3 / +0.4 / +0.2      （DC 归零）
范围 −115 … +117              （全量程）
削顶 0.0%                     （无裁切）
```

### 怎么把 bias 算出来（通式）

```
q = (acc · M) >> shift          # 线性
⇒ 想把某通道的 DC 移动 Δq，bias 要减  Δq / m，其中 m = M >> shift
```
本轮：`m = 435501648 / 2^37 = 0.003168`，所以 Δq=10 对应 `bias − 3157`。

## 五、给模型侧的建议

**star 系列需要按 v5 的约定重导一遍**，和 redsky v5 做的事完全一样：

| 项 | 现在 | 应该是 |
|---|---|---|
| 末层 `qlo/qhi` | `0 / 255` | **`129 / 127`**（有符号） |
| 末层 `shift` | 39 | **37**（或 38，见下） |
| `s_out` | 按 offset-binary 定的 | 按有符号区间重算，让 σ 落进 30~50 |
| 逐通道 DC | 未做 / 用训练集 | 按板场景或**多场景混合**重标 |

- `shift=38` 更保守（σ 15.5，绝对不削顶）；`shift=37` 更好看（σ 30.9）但离削顶边界更近（−115/+117，余量 10 级）。
- 如果重导时把 `s_out` 调到让 σ 落在 40~50，就不用靠 shift 硬拉，余量也更舒服。
