# 给模型/训练侧：输出层 DC 标定方法（板侧验证版）

> 日期：2026-10-27 晚（板侧实测）
> 读者：负责训练与导出权重的模型侧
> 前置：`reports/FOR_MODEL_QUANT_CONTRACT.md`（量化契约，仍然有效）
> 本文只讲**一件事**：末层（L11）逐通道 DC 该怎么定。
>
> **一句话**：DC 要按**风格参考图的通道均值**对齐（目标 `q = 参考图均值 − 128`），
> 换算用 `Δbias = Δq × 2^shift / M`，迭代两轮；**千万不要"三通道归零"**——那会把风格抹成中性灰。
>
> ⚠ **本文取代 `FOR_MODEL_QUANT_CONTRACT.md` §4.3「去掉逐通道直流偏置 / 保证三通道均值相等」**。
> 那一条是 10-26 的推测，10-27 板上实验证明它是错的（见 §一）。除 §4.3 外，那份文档的其余内容仍然成立。

---

## 〇、一页结论：模型侧该改什么

### 必须做的三条

| # | 做什么 | 为什么 |
|---|---|---|
| **1** | 末层 DC 按**风格参考图**标定：目标 `q̄_c = ref_mean_c − 128`；**不要**把三通道归零 | 原厂的色彩平衡本来就基本对（`starry_v7` 的 B−R 只差 5.4 级），真正的错是整体偏正 ~115 级 |
| **2** | 换算用 `Δbias_c = Δq_c × 2^shift / M_c`，**迭代两轮** | 公式三次实验误差 <1 级；但削顶会压低实测均值，一轮不够（B 通道最明显） |
| **3** | **R/G 的输出幅度加大**（现在 σ 只有 B 的一半），在导出侧做 | 三通道共用同一个 M 时，R/G 的 σ 只有参考图的 47%~65%，这是网络输出幅度问题 |

### 不要动的两条

| # | 不要 | 原因 |
|---|---|---|
| 4 | 不要改 11 个中间层的 Q 头（`qlo=0/qhi=255`） | 与 `spec.json` 的 `activation_signed` 和描述符 `xorin` 一一对应，是对的 |
| 5 | 不要用 offset-binary 末层（`qlo=0/qhi=255`） | 当前显示链对右半 `^0x80`（等价按有符号 +128），offset 数据会被整体 +128 并翻转色偏方向（§六） |

### 末层四个字段的最终形态

| 字段 | 值 | 说明 |
|---|---|---|
| `qlo` | **129**（= 有符号 −127） | 不是 128；对称区间 `[-127,127]` |
| `qhi` | **127** | |
| `shift` | 由标定决定（建议 37~38） | 见 `FOR_MODEL_QUANT_CONTRACT.md` §4.2 |
| `bias[0..2]` | `m·(conv_mean_c + b_c) = ref_mean_c − 128` | 本文的主题 |

## 一、为什么"三通道归零"是错的（这是今晚最重要的一课）

### 1.1 踩坑记录

我先按"三通道均值归零"去调 `starry_v8_signed`。结果：**画面变成中性灰，星空风格被抹掉了**。
原因很直接——**星空这张画本身就是蓝的**，把它调成 R=G=B 等于把风格本身删掉。

### 1.2 按参考图一算就明白了

用板侧记录的原厂 DC（`starry_v7_signed`，参考图取 `starry_night_鲜艳.jpg`）：

| | 原厂 | 参考图要的 | 差 |
|---|---|---|---|
| B−R（色彩平衡） | +55.6 | **+50.2** | **只差 5.4** |
| 整体亮度（中间值） | +90 | **−25** | **亮了 115 级** |

⇒ **色彩平衡几乎就是对的，唯一的问题是整体偏正 115 级、导致 21.4% 撞顶。**
正确修法是**整体下移 ≈115**，而不是逐通道归零。

### 1.3 用参考图自己的数字验证"原厂其实没错"

三张参考图的实测统计（**你自己三行 numpy 就能复现**，见附录 A）：

| 参考图 | R | G | B | B−R | σ R/G/B |
|---|---|---|---|---|---|
| `starry_night.jpg` | 76.4 | 92.4 | 110.4 | **+34.0** | 49.7 / 51.9 / 53.8 |
| `starry_night_鲜艳.jpg` | 78.3 | 101.9 | 128.5 | **+50.2** | 56.9 / 58.6 / 62.6 |

再看板侧 10-27 从 DDR 里读到的原厂输出（`starry_v8` 按无符号解读，即"导出本意"）：

| | R | G | B | B−R |
|---|---|---|---|---|
| 原厂输出（无符号解读） | 75.6 | 100.9 | 137.0 | **+61.3** |
| `starry_night.jpg` 参考 | 76.4 | 92.4 | 110.4 | +34.0 |

**R 差 0.8 级、G 差 8.5 级**——网络的 DC 本来就贴着参考图。B 偏高 26 级（偏蓝偏多），
但方向是对的（参考图本身 B 就比 R 高 34）。

⇒ **"三通道均值 75/100/119 ⇒ 偏蓝 ⇒ 要去直流"这个推断是错的**：+44 的 B−R 不是病，是风格（参考图要 +34 ~ +50）。
`FOR_MODEL_QUANT_CONTRACT.md §4.3` 据此要求"保证三通道均值相等"，方向错了，**请忽略那一条**。

### 1.4 那"偏蓝"的观感是怎么来的

来自**三个错误叠加**，跟 DC 的三通道差异无关：

| 现象 | 真因 | 出处 |
|---|---|---|
| 整体发白 | 把 offset-binary 的数据按有符号显示（+128） | `FOR_MODEL_QUANT_CONTRACT.md` §二 |
| 大面色块 | 末层 `qlo=0` 触发 ReLU，负半轴被削 | 同上 |
| 屏摄"强蓝" | **USB 采集卡把色偏放大约 1.5 倍** | `COLOR_CHECKER_CALIB_2026-10-27.md` §三 |

采集卡要特别记住：同一画面 DDR 里 B−R=+25.6、采集卡出来 +67.8。**判色一律用 DDR 直读，不要看屏摄。**

## 二、DC 到底存在哪、它到底是什么

### 2.1 物理位置（3 个 word）

| 层 | blob word | DDR 地址 | 内容 |
|---|---|---|---|
| L11 | **3560 / 3561 / 3562** | `0x06F037A0 / A4 / A8` | R / G / B 的 int32 bias |

固化工具：`tools/freeze_dc.py`（只替换这 3 个 word，权重/M/Q 头逐字不动，重算 XOR）。
Q 头在 word 3608（`0x06F03860`），M 在 word 3576+2k。

### 2.2 DC 的解析式（这是全部方法的根）

`requant.v` 的末层算术是（`RHE` = 四舍六入五成双，`m = M/2^shift`）：

```
q_c = clamp( RHE( acc_c · M_c , shift ), −127, +127 )
acc_c = conv_c + bias_c
⇒ 在未削顶区间内：  q̄_c = m_c · ( conv_mean_c + bias_c )
```

屏幕上的 u8 = `q + 128`。所以要屏幕均值等于参考图均值 `ref_c`：

```
目标： q̄_c = ref_c − 128
⇒      bias_c = (ref_c − 128) / m_c − conv_mean_c          …… (式 1)
```

**式 1 说清了两件事，也解释了为什么模型侧"算一次"不够：**

1. `bias` 只决定**常数项**：改 bias 会让 q̄ 平移 `m·Δbias`，**与场景无关**。
2. `conv_mean_c` 是**网络对当前输入场景的输出均值**，**随场景变**：
   同一套权重，拍晴天和拍夜景，`conv_mean` 差很多 ⇒ 固定的 `bias` 只能对一个场景最优。

> 这就是"DC 是每个风格 × 每个场景的组合"的数学形式。
> 详见 §九——请务必按那一节的预期管理来做，不要以为标一次就永久有效。

### 2.3 为什么不能靠"把三通道归零"绕过场景问题

归零等价于把 bias 设成 `−conv_mean_c`，而 `conv_mean_c` 是**输入的函数**。
所以"归零"只是把 DC 对齐到标定那一帧的输入，**没解决场景依赖**，却额外删掉了风格需要的色偏（B−R = +34~+50）——**双重损失**。

## 三、换算公式（今晚三次实验验证，误差 <1 级）

### 3.1 公式与推导

由 `q̄ = m·(conv_mean + bias)`，对 bias 求差分（conv_mean 与 bias 无关）：

```
Δq̄ = m · Δbias         m = M / 2^shift
⇒   Δbias = Δq̄ · 2^shift / M
```

工程上把 `2^shift / M` 记作 **`per`**（"每 1 级 q 需要多少 bias 单位"）：

```
Δbias = Δq̄ × per          per = 2^shift / M
```

**注意 `per` 是每个变体（甚至每个通道）自己的常数**，因为它由该层的 `M` 和 `shift` 决定：

| 变体 | M | shift | `m = M/2^shift` | **`per = 2^shift/M`** | 移动 10 级 q 需要 |
|---|---|---|---|---|---|
| `starry_v7_signed` | 725,612,887 | 37 | 5.2795e−3 | **189.41** | 1,894 |
| `starry_v8_signed` | 1,064,584,830 | 37 | 7.7459e−3 | **129.10** | 1,291 |
| `starry_old_signed` | 977,076,790 | 38 | 3.5546e−3 | **281.33** | 2,813 |

（`M`/`shift` 均从 `weights/*_dc/rowpipe_blob.bin` 逐字读出，Q 头 = `0x001FE065` 或等价的
`shift/qlo=129/qhi=127` 组合。）

### 3.2 四步工作流（20 秒一轮，不用重烧）

```
第 1 步  量参考图：ref = [img[:,:,i].mean() for i in range(3)]
         目标 q̄ = ref − 128

第 2 步  量当前输出：从 DDR 直接读结果帧，按有符号统计三通道均值 q̄_cur
         （不用屏摄！采集卡会把色偏放大 1.5×）

第 3 步  算：Δq̄ = (ref − 128) − q̄_cur
             Δbias = Δq̄ × per          per = 2^shift / M

第 4 步  写：bias_new = bias_cur + Δbias
         写 DDR 前必须 halt，否则写入丢失（回读还是原值）
```

### 3.3 三次实验的实测误差（这就是"<1 级"的出处）

用上表的 `per` 把实际施加的 `Δbias` 换算回 `Δq`，再与实测达成的均值对比：

| 变体 | 施加的 Δbias（R/G/B） | 换算 Δq = Δbias/per | 目标 q̄ | **实测达成** | **误差** |
|---|---|---|---|---|---|
| v7（per 189.41） | −20873 / −22805 / −29435 | −110.2 / −120.4 / −155.4 | −50 / −26 / 0 | −50.3 / −26.1 / +0.8 | −0.3 / −0.1 / +0.8 |
| v8（per 129.10） | −16473 / −17700 / −20179 | −127.6 / −137.0 / −156.3 | −52 / −36 / −18 | −52.0 / −36.1 / −18.2 | 0.0 / −0.1 / −0.2 |
| old（per 281.33） | −34266 / −35025 / −38401 | −121.8 / −124.5 / −136.5 | −52 / −36 / −18 | −51.8 / −35.9 / −17.7 | +0.2 / +0.1 / +0.3 |

**三个变体、九个通道，误差全在 ±0.8 级以内。公式可以直接用。**

而且有一个独立交叉验证：用 v8 的 `Δq = Δbias/per` 反推它**修正前**的均值，得
`75.6 / 100.9 / 138.1`，与另一个独立测量（同一帧按无符号解读的 `75.6 / 100.9 / 137.0`）
吻合到 1 级以内 —— **两条互不相干的路径给出同一个数，说明这条线性关系是对的。**

### 3.4 如果你要改 `M`（逐通道增益），`per` 会变，公式要重推

改 `M` 时 `m` 变了，**同样的 bias 会产生不同的 DC**：

```
原来： q̄ = m ·(conv_mean + b)        = T
M 加倍：q̄' = 2m·(conv_mean + b')     = T      （要求 DC 不变）
⇒      b' = b − T /(2m)  =  b − T·per_old / 2
```

`per_old` 是**改 M 之前**那个 `per`。板侧实测过这一条（v7 的 M×2 试验），而且**逐位对得上**：

```
目标 q̄ = (−50, −26, 0)，per_old = 189.411，R/G 的 M 加倍
R: b' = 1975  − (−50)×189.411/2 = 1975  + 4735 = 6710
G: b' = 21393 − (−26)×189.411/2 = 21393 + 2462 = 23855
B: M 不变 ⇒ b' = 37818
板侧最终写进 DDR 的正是 6710 / 23855 / 37818   ← 完全一致
```

⚠ **但这是一次性的**：`b` 只能把 DC 对到**标定用的那一帧**。换成另一个场景，
`conv_mean` 变了，2 倍 M 的通道会漂移 2 倍——见 §九。

## 四、为什么要迭代两轮（削顶效应）

### 4.1 机制

板侧读到的 `q̄` 是**削顶之后**的均值：

```
实测 q̄_meas = E[ clamp(q, −127, +127) ]  ≤  E[ q ] = 真实 q̄
```

原厂配置下 `q̄_B` 的无削顶值 ≈ **+156**，早已越过 +127 的上界（这也是 B 通道撞顶最严重的原因）。
**削顶把测量值永远压低**，于是：

1. 第 1 轮你按偏低的目标算 `Δbias`，实际施加的位移是"够"的——但**测出来的还是偏低**；
2. 修完一轮、削顶消失之后，真实均值才"浮出水面"，**比第 1 轮的预测值更高**；
3 **所以第 1 轮的结果通常还差一点**，需要用实测值再补一次。

### 4.2 经验规律

| 通道 | 情况 | 轮数 |
|---|---|---|
| R / G | σ 小、撞顶少（0.1%~1%），测量基本可信 | **1 轮到位** |
| B | σ 最大（55~62），撞顶比例高，`q̄_meas` 被压最狠 | **2 轮**（第 1 轮后补差量） |

### 4.3 第二轮怎么做

```
第 2 轮：Δbias2 = (目标 q̄ − 第 1 轮实测 q̄) × per
         bias2 = bias1 + Δbias2
停止判据：|实测 q̄ − 目标 q̄| ≤ 1 级  且  撞顶 < 1%
```

三套变体的实际收敛情况（`weights/*_dc/README.md`）：

| 变体 | 第 1 轮后误差 | 是否需第 2 轮 |
|---|---|---|
| v7 | −0.3 / −0.1 / +0.8 | 达标（B 差 0.8，边缘） |
| v8 | 0.0 / −0.1 / −0.2 | 达标 |
| old_signed | +0.2 / +0.1 / +0.3 | 达标 |

> 注意上表是**已经迭代之后**的终值。B 通道仍然最容易残留偏差；
> 若你的变体 B 撞顶 >5%，请先按 §五 或 §八 处理量程，再谈 DC——**在削顶严重时标 DC 是徒劳的**。

## 五、逐通道 `M`：修对比度的杠杆，但别滥用

### 5.1 事实：三通道共用同一个 M

三套 starry 变体的 L11，`M[0]=M[1]=M[2]`（逐字读出，见 §三 的 `per` 表）。
而实测 σ 差得很远：

| 变体 | σ R | σ G | σ B | 参考图 σ R/G/B | R/G 占参考的比例 |
|---|---|---|---|---|---|
| `starry_v7_signed` | 26.9 | 26.7 | 55.6 | 56.9 / 58.6 / 62.6（鲜艳） | **47% / 46%** |
| `starry_v8_signed` | 34.0 | 37.7 | 61.9 | 49.7 / 51.9 / 53.8（night） | **68% / 73%** |
| `starry_old_signed` | 28.7 | 28.1 | 23.3 | 49.7 / 51.9 / 53.8（night） | 58% / 54% |

三通道共用一个 `M` ⇒ 这是**网络输出的逐通道幅度差异**，不是量化器的问题，也不是 DC 的问题。
（B 的 σ 正常，R/G 偏小一半。）

### 5.2 板侧可以怎么修，代价是什么

格式**支持**逐通道 M（M 有 16 个槽，按通道使用），所以板侧能直接给 R/G 加倍：

| 项 | 加倍前 | 加倍后 | 代价 |
|---|---|---|---|
| σ R | 27.0 | **49.3** | |
| σ G | 26.8 | **51.9** | |
| σ B | 54.6 | 55.5 | |
| **贴轨（撞顶）** | **0.1%** | **4.4%** | ← 这就是代价 |

σ 达标了，但撞顶从 0.1% 涨到 4.4%（虽仍 <5%，但余量没了）。
**这一版没有固化进 `_dc` 变体**（`weights/starry_v7_signed_dc/README.md` 明确记录"已撤回"）。

### 5.3 所以请你们在导出侧解决

板侧改 M 有三个坏处：① 牺牲动态范围；② `per` 变成逐通道的，以后每次调 DC 都要单独算；
③ **DC 会随场景漂移**（`q̄` 里 `m·conv_mean` 那一项随场景变，M 加倍就漂 2 倍）。

模型侧做这件事则是**免费的**：训练/导出时把 R/G 的输出幅度放大（等价于让三个通道的
`s_out` 各自标定，而不是共用一个），量化尺度天然自洽，不用拿动态范围去换。

具体做法见 §八。

## 六、signed vs offset-binary：为什么必须是 signed

### 6.1 同一帧数据的两种解读（板侧实测，`starry_v8`）

| 解读 | R | G | B | B−R | 结论 |
|---|---|---|---|---|---|
| **有符号**（= 屏幕实际所见） | 189.2 | 147.3 | 135.0 | **−54.2** | 强暖（偏黄红） |
| **无符号**（= 导出本意） | 75.6 | 100.9 | 137.0 | **+61.3** | 强蓝 |

**同一个画面，两种解读的色偏方向相反。** 因为显示端对右半做 `^0x80`
（`rtl/style/style_display.sv:107`），等价于"按有符号 +128"。

### 6.2 判定

- 导出端如果按 offset-binary（`qlo=0 / qhi=255`）写，屏幕会整体 +128：
  75.6→203.6、100.9→228.9、137→265→削到 255。**画面泛白、色偏反转。**
- 所以 **末层必须 signed**：`qlo=129`（= −127）、`qhi=127`，数据本身零中心。（域不匹配的逐位取证见 `reports/line_by_line/08_quant_convention.md` §六；那份文档同时指出"关掉 `^0x80` 就能用 offset"，但**既然显示链已经冻结，模型侧就按 signed 走**。）
- `_signed` 系列是对的；**`offset` 系列在当前显示链下不可用**（除非关掉右半的 `^0x80`）。

### 6.3 与 DC 的关系

一旦确定 signed，DC 的语义就唯一了：`q̄ = ref − 128`，屏幕均值 = `q̄ + 128 = ref`。
offset 约定下这个式子不成立（会差 128），**两件事必须一起定，不能分开调**。

### 8.2 三个可能的原因（按我判断的可能性排序）

| # | 可能原因 | 怎么验 |
|---|---|---|
| 1 | **三个通道共用一条 `s_out`**，而 R/G 的实数输出幅度本来就比 B 小 | 用校准集统计末层 conv 输出的逐通道 `std`，若 R/G 确实只有 B 的一半，就是这个 |
| 2 | 训练 loss 对色度通道的约束弱（感知/风格 loss 对亮度敏感、对色度不敏感） | 看 loss 分解里 R/G 的梯度量级 |
| 3 | 逐通道 `s_out` 已做但标定数据偏"亮中性"场景，R/G 的动态被压 | 换多场景校准集重算 `s_out` |

### 8.3 建议的修法

**逐通道 `s_out`**。导出公式（末层）：

```
s_out_c = ( p99.5_c − p0.5_c ) / 255          # 逐通道，不要共用
M_c     = rint( s_in · s_w_c / s_out_c · 2^shift )
bias_c  = 见式 1（用新的 m_c 重算）
```

预期效果：R/G 的 σ 拉起来，同时**不需要**板侧把 M 加倍 ⇒ 撞顶不必从 0.1% 涨到 4.4%。

## 九、DC 的适用边界（请务必按这个做预期管理）

**这一节是本文最容易被忽略、但最容易造成返工的部分。**

### 9.1 结论

**`bias` 只能修"常数"，修不了"场景"。** 由式 1：

```
q̄_c = m_c · conv_mean_c(scene) + m_c · bias_c
       └── 随场景/光照/内容变化 ──┘   └── 你标定的常数 ──┘
```

- 标定用的那一帧确定了一个 `bias`，它让 `q̄` 命中参考图；
- **换场景 ⇒ `conv_mean` 变 ⇒ `q̄` 跟着漂**，漂移量 = `m·Δconv_mean`；
- 所以"把 DC 算进权重里"= 让**某个场景最优**，**不是**"永久正确"。

### 9.2 漂移有多大（可估算）

```
Δq̄ = m · Δconv_mean          （bias 固定，只有 conv 项随场景变）
```

对 `starry_v7_signed`（`m = 5.2795e−3`）：`conv_mean` 每变 100 个累加器单位，`q̄` 漂 **0.53 级**；
变 1000 个单位漂 **5.3 级**。换个说法：1 级 q = `per = 189` 个累加器单位，
**换场景只要让 `conv_mean` 变 ±190，DC 就偏 1 级。**

**这就是"单一固定 DC 只能对某个场景最优"的量化含义。**

### 9.3 三条工程对策（按成本排序）

| # | 做法 | 成本 | 适用 |
|---|---|---|---|
| 1 | 用**多场景混合**校准集取 `conv_mean` 的中位数 | 低（重导一次） | 通用场景 |
| 2 | 把 `bias` 标到"最常用场景"，接受次要场景 ±10 级偏差 | 零 | 场景固定的产品 |
| 3 | 板侧在线 AE 联动（按帧亮度动态微调 bias） | 高 | 光照变化大 |

**请至少做第 1 条**，并在交付说明里写清"这套 DC 是用哪些场景标的"。

### 9.4 明确不要做的事

- ❌ 不要以为"导一次就永久有效"；
- ❌ 不要用**训练集统计**代替风格参考图（`COLOR_CHECKER_CALIB` 已证明模型侧离线预测 +21.4
  与板上实测 +25.6 吻合，说明偏差来自**场景差异**而非计算错误）；
- ❌ 不要用屏摄判色（采集卡放大 1.5×）。
