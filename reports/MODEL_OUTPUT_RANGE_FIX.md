# 风格化输出泛白问题：模型侧修改指引

> 日期：2026-10-25
> 面向：负责模型训练/导出的会话
> 现象：板子上右侧（风格化）画面**泛白、平淡、像蒙了层白雾**，而左侧原画正常。
> 结论：**不是显示链路问题（已修）**，是模型输出层的数值分布问题。

---

## 一、核心结论（一句话）

**模型输出的 INT8 值只用了满量程的 20%，且整体偏正（没有 zero-center），导致显示后动态范围坍塌，画面看起来泛白。**

---

## 二、证据（板上实测，非推测）

### 2.1 DDR 里读出的原始 INT8 值分布

从风格帧缓冲区（`0x05800000`）直接读内存采样 96 个像素：

| 通道 | 均值 | σ | 实测范围 | 占用级数 | **量程利用率** |
|---|---|---|---|---|---|
| **R** | **23.2** | **13.4** | 2 .. 46 | 45 | **17.6%** |
| **G** | **30.2** | **15.0** | 0 .. 51 | 52 | **20.3%** |
| **B** | **47.9** | **14.9** | 14 .. 68 | 55 | **21.5%** |

INT8 满量程是 −128..127（256 级）。

### 2.2 三个明确的偏差

| 偏差 | 实测 | 理想 | 影响 |
|---|---|---|---|
| **均值偏正** | R=23, G=30, B=48 | ≈ 0 | 显示后整体提亮，暗部丢失 |
| **σ 偏小** | 13–15 | 50–70 | 对比度不足，画面平 |
| **范围偏窄** | 2..68 | −128..127 | **只用 20% 量程** |

### 2.3 显示端的直接后果

| 区域 | 亮度均值 | σ | P5–P95 跨度 | 直方图 |
|---|---|---|---|---|
| **左半原画** | 156 | **64.8** | **189** | 均匀分布 |
| **右半风格** | 179 | **14.5** | **46** | **76% 挤在 160–192 一段** |

**右半的动态范围只有左半的 1/4。** 这就是"泛白"的物理原因 —— 所有像素都落在很窄的亮区间里，没有暗部和亮部层次。

## 三、硬件侧的量化和参数（模型会话需要知道）

### 3.1 每层 requant 的数学形式

```
q = clamp( RHE( relu?(acc) · M , shift ) )
其中 M / 2^shift ≈ s_a · s_w / s_out
```

- `M`：signed 32 位乘法因子
- `shift`：0..63
- `RHE`：round-half-to-even（**不是四舍五入**，`.5` 取偶）
- 饱和到 `qlo .. qhi`

**BN 常数形式**：`acc*M + B`，M 为 signed16、B 为 signed32、shift 为 8 位（这是 docs 里记录的约定，实际 RTL 每层可变）。

### 3.2 权重 blob 里每层的字段布局

blob 总大小 **22,512 B**（1,407 个 16 B beat / 903 beat 的 DDR 记录）。

RTL 解析顺序（`rowpipe_engine.v`）：

```
S_M:  每层 8 组，每组 64 bit => M[31:0] + mid[31:0]
      ld_m    <= whold[uc*64 +: 32]
      ld_mid  <= whold[uc*64+32 +: 32]

S_Q:  最后一拍读 64 bit 头
      ld_shift <= whold[5:0]      // 6 bit
      ld_qlo   <= whold[13:6]     // 8 bit signed
      ld_qhi   <= whold[21:14]    // 8 bit
```

**即每层 = 9 × ci 个权重(8bit packed) + 4 字节 bias + 8 组 M/mid + 1 个 q 头。**

### 3.3 最后一层的特殊地位

**输出层（L11）的 `shift` 和 `M` 直接决定输出量程。**

当前 L11 的 shift/M 是在训练导出时由 `s_a · s_w / s_out` 算出来的。如果 `s_out` 取的是**训练集激活统计的某个分位数**（常见做法），而实际推理输入的激活分布与训练集不同，就会导致输出只占一小段。

## 四、修改方案（三个层次，从轻到重）

### 方案 A：训练时约束输出层的激活分布 ⭐ 推荐

**目标**：让 L11 的输出在 INT8 上铺满 −128..127。

**做法**：

1. **训练时监控 L11 输出的激活分布**
   ```python
   # 在训练循环里记录最后一层的输出
   out = model(x)
   print(f"L11 out: min={out.min():.3f} max={out.max():.3f} "
         f"mean={out.mean():.3f} std={out.std():.3f}")
   ```
   健康指标：`mean ≈ 0`（相对 `s_out` 归一化后），`std` 应使 `±3σ` 接近饱和边界。

2. **加输出层的 zero-center 约束**
   如果 `mean` 明显偏离 0，说明有系统性 bias。检查：
   - 最后一层卷积是否带 bias
   - BN 层是否被正确折叠（`acc*M + B` 里的 B 若不为 0，会引入偏移）

3. **重新标定 s_out**
   导出时 `s_out` 不要用固定常数，而是用**实际推理输出**的动态范围：
   ```python
   # 用校准集跑一遍，取实际输出的分位数
   s_out = (p99_9 - p0_1) / 255.0   # 覆盖 99.8% 的样本
   ```

**验证**：导出后量化模型跑校准集，检查输出 INT8 的 `std ≥ 45`（对应满量程的 ~35%）。

---

### 方案 B：只在导出环节重新标定输出层（不改训练）

如果不想重训，可以只改导出脚本：

1. 拿已有权重，用校准集（一批真实输入图像）在前向推理中**统计 L11 实际输出**
2. 按实际分布的 `p0.5 .. p99.5` 重新计算 `s_out`
3. 反推新的 `M` 和 `shift`：
   ```
   M = round( s_a · s_w / s_new_out · 2^shift )
   shift = 选择使 M 落在 signed32 范围且不溢出的值
   ```
4. 只更新 blob 里 L11 的 M/shift 字段（其余层不动）

**风险**：只改最后一层，前面各层的量化误差仍在；且若前面层的输出分布也已收缩，单改 L11 效果有限。

---

### 方案 C：量化感知训练（QAT）覆盖输出层

最彻底的做法：

1. 在 QAT 阶段**显式模拟输出层的量化**：
   ```python
   # 伪代码
   out_fp = model(x)
   scale = observer.get_scale(out_fp)      # 让 observer 覆盖实际范围
   out_q = fake_quantize(out_fp, scale)    # 模拟 INT8
   loss = loss_fn(out_q, target)
   ```
2. 让 loss 直接作用在量化后的输出上，网络会主动把值域拉开
3. 训练若干 epoch 后导出

**注意**：这套 rowpipe 用的是 `acc*M+B` 形式（不是标准 TFLite 的 `scale+zp`），导出工具需要把 QAT 的 `scale/zero_point` 换算成 `M/shift`。

## 五、必须一并检查的三个点

### 5.1 输出层是否有 bias 导致整体偏正

实测均值 R/G/B = 23/30/48，**B 偏得最多（48）**。

这很可疑 —— 如果 B 通道有系统性正偏，说明：
- 最后一层的 bias 没有被正确折叠进 `M/B` 常数
- 或者 `s_out` 的 zero-point 取错了（没做 zero-center）

**检查**：打印最后一层的 `bias` 和导出的 `B` 常数，确认量级合理。

### 5.2 训练/推理的输入预处理是否一致

如果训练时输入做了归一化（如 `(x-0.5)/0.5`），但板子上的固件送进去的是原始 8-bit，**输入分布不同会直接导致输出分布漂移**。

**检查**：板子上的输入是什么范围？训练时是什么范围？两者必须一致。

### 5.3 训练集与现场场景的差异

如果训练集是某类图像（如绘画），而现场拍的是摄像头实时画面，激活分布本来就不同。

**建议**：用**摄像头实际采集的画面**做校准集，而不是训练集。

## 六、验收标准（给模型会话）

导出新权重后，用下列指标验收（这些是板上可以量化的）：

| 指标 | 当前实测 | 目标 |
|---|---|---|
| **输出 INT8 均值** | R=23, G=30, B=48 | **\|均值\| < 15** |
| **输出 INT8 σ** | 13–15 | **≥ 45** |
| **输出 INT8 范围** | 2..68（占 20%） | **覆盖 ≥ 70%（−90..90 以上）** |
| **板上右半 σ**（显示后） | **14.5** | **≥ 35** |
| **板上右半 P5-P95 跨度** | 46 | **≥ 120** |

**测量方法**（我可以提供工具）：
- DDR 直读：`0x06F00000` 是权重，`0x05800000` 起是 6 个风格帧 slot
- 每个 32-bit 字 = `{8'b0, R, G, B}`，取低 24 位拆成三个 INT8
- 采集卡抓图后算 σ 和 P5-P95

## 七、当前可用的替代方案（如果模型侧短期改不了）

**RTL 后处理拉伸**（我可以实现，约 30 分钟）：

在 `style_display` 里，XOR 0x80 **之前**加线性变换：

```verilog
// 把 [mean-3σ, mean+3σ] 拉伸到 [-128, 127]
// 用实测：mean≈34, σ≈14  =>  gain ≈ 256/(6*14) ≈ 3.0
wire signed [8:0] in  = rd_pixel[23:0];     // 按通道拆
wire signed [8:0] out = clamp((in - 34) * 3);
```

**优点**：不用重训练，当天就能看到效果
**缺点**：噪声同步放大 3 倍（σ 13.4 → 40，视觉上会有颗粒感）

---

## 八、给模型会话的最小改动清单

如果时间紧，按这个顺序：

1. **先查**：输出层 bias 是否导致整体偏正（最可能的单点原因）
2. **再查**：训练/推理的输入预处理是否一致
3. **然后**：用现场采集的画面做校准集，重新标定 `s_out`
4. **最后**：如果前三步不够，才上 QAT

**不要一上来就重训练** —— 先从"重新标定 s_out"这个低成本动作试起。
