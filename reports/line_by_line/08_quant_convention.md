## 结论（5 条，每条附可复现证据）

### 结论 1 —— 权威定义在**参考交付包**里，不在工作区任何导出脚本里

`starry_cap8_20261024/rtl/INTERFACE.md §8`（350 行，此前 4 处引用但"找不到"的那份）+ `network/spec.json`
+ `ref_full_model.py` 三者互证，构成这套 blob 的权威契约。工作区里唯一的导出器
`demo/reports/rowpipe/tools/blob_export.py` 是**事后反推重写**的，项目自己已经判定它"语义不等于硬件"
（`demo/reports/rowpipe/INK_EXPORT_ROOT_CAUSE.md` §1："我的模拟器与真实硬件表现**完全相反**"、
§2："这个格式的第一个实现就是我写的 `blob_export.py`，而它是从我对 RTL 的阅读推出来的，
**从未与已知可用的参照对过**"）。**本报告不把 blob_export.py 当权威，只当对照物。**

可复现：`grep -rn "LAYER_SIGNED" demo/reports/rowpipe/tools/blob_export.py` → 第 60 行；
`starry_cap8_20261024/weights/weights_blob_cap8_starry.bin` 的 XOR = `0xc7eaf900`，
与 `rowpipe_keys/software/firmware/rowpipe_weights.h.orig`（git 原版）**逐字节相同** —— 这是唯一的
"板上已知可用"基准（`demo/reports/rowpipe/REFERENCE_PACKAGE_FOUND.md` §1）。

### 结论 2 —— 输出层是 **offset-binary uint8 [0,255]**，不是 signed int8 [-128,127]

三条独立证据同时指向 offset-binary：

| # | 证据 | 位置 |
|---|---|---|
| a | 输出层的 `s_out` 和量化区间是**手工追加的第 13 项**：`s_out = 1/255`，`qrange = (0,255)` | `ref_full_model.py:78-80` |
| b | 量化总纲："activation: **uint8 非对称，ReLU 后非负故 zero-point 恒为 0**" | `starry_cap8_20261024/network/spec.json:16` |
| c | 结果帧数值域："源帧是原始 u8 …… 壳侧**不需要做任何偏移**" | `starry_cap8_20261024/rtl/INTERFACE.md:120-121` |

⇒ **L11 的正确约定 = `qlo=0, qhi=255`**（shift 按标定：已知可用的 cap8-starry blob 是 **39**，
板上正在跑的这一份 redsky_v4 是 **37**）。
Lead 今天的改动 `qlo=0/qhi=255 → qlo=-128/qhi=127` **违反了权威契约**。

### 结论 3 —— `qlo` 在权威格式里是"该层**输出**的量化下界"，RTL 却把它当 ReLU 使能；末层语义分叉但数值恰好等价 —— 今天正是栽在这里

- 格式侧语义：`quant 的 qlo/qhi = 该层【输出】的量化区间 = 下一层的输入 qrange（末层 (0,255)）`
  （`REFERENCE_PACKAGE_FOUND.md` §3 明文；`INTERFACE.md:234` 只给了位域，语义由 spec 的 qrange 链给出）。
- RTL 侧语义：`ar = (qlo_r < 0) ? a : relu(a)`（`requant.v:90`，ARCH=1 的同款在 `:114`）。
- 对 11 个中间层，两种语义**恰好等价**（输出区间 `[0,255]` ⟺ 有 ReLU；`[-127,127]` ⟺ 无 ReLU）。
- 对 L11 不等价：输出区间是 `[0,255]`（偏移域）但模型末层**没有 ReLU**
  （`ref_full_model.py:138-139`：`if i + 1 < n and rng[i+1][0] >= 0` —— i=11 时 `i+1 < n` 为假，
  **末层不加 ReLU**）。于是 `qlo=0` 会让 RTL 对末层加 ReLU。
  **但这一步 numerically 无害**：M>0 ⇒ `clamp(relu(acc)·M, 0,255) ≡ clamp(acc·M, 0,255)`。
  所以"L11 标 ReLU 层会半波整流出灰糊"这个论断（`BLOB_FORMAT.md` §8 bug#3）**在本格式下是错的**。

### 结论 4 —— `bias` 里确实含 `128·Σw`（无符号层修正），且**不含** `−128·s_out`

用 blob 里 L11 的 36 个权重 beat（4 个输入通道 × 9 tap，每 beat 低 3 字节 = cout 0/1/2）实测：

```
Σw (按 int8 累加 36 个 tap)   = [ 699,  652,  370]     (redsky_v4 / .before_l11signed)
128·Σw                        = [89472, 83456, 47360]
bias (word3560..3575 int32)   = [63695, 59739, 35051]
bias − 128·Σw                 = [-25777, -23717, -12309]
```

`bias − 128·Σw = b0`（模型自身 conv bias 的累加器计数形态），不是 0 —— 这正好符合
`INTERFACE.md:205` 的"偏置 …… **已含无符号层的 `128*Σw` 修正**"：修正是**叠在** b0 上的。
因为读入 tap 是 `t' = q−128`（`conv3x3_core.v:20-24`），所以

```
acc = b0 + Σw·q       (q = 上一层输出的 uint8 原值)
```

⇒ **acc 对真实激活 q 单调递增（Σw 全为正）**。这一条直接否定了"存在 −Σw 负斜率"的假设。

不含 `−128·s_out` 的证据是"族内反证"：`g065/g075/g085` 三个变体 **bias 完全相同**
（`[28575,41293,53398]`）而 **M 相差 2.4 倍**（2.83e8 → 6.83e8）。若 bias 里含 `−128/m`
项，它必须随 M 变化 —— 它没有。⇒ **committed 的 L11 输出不带 −128 偏移，是纯偏移域
（0=黑）**，与结论 2 自洽。

### 结论 5 —— 泛白/反相的真凶是**偏移域数据 + 有符号显示**这一对矛盾，`qlo` 只是把它揭开

显示端：`rgb = right_side ? (rd_pixel[23:0] ^ 24'h808080) : rd_pixel[23:0]`
（`rtl/style/style_display.sv:107`），注释写着"stylised buffer stores INT8 with a +0x80 bias
(0 = mid grey)"。对字节做 XOR 0x80 = **+128 的模 256 旋转**：
`0x00..0x7F → 128..255`（亮），`0x80..0xFF → 0..127`（暗）。

- 模型写的是**偏移域 u8（0=黑）**，显示却按**有符号居中（0=中灰）**解释 ⇒ 整幅 +128 LSB ⇒ **泛白**。
- 量化对账：`MODEL_OUTPUT_RANGE_FIX.md` §2.3 板上实测右半"亮度均值 **179**、σ 14.5、
  76% 挤在 160–192"；本报告用 RTL 算术跑已知可用 blob 得 L11 输出 q ∈ [30,68]（mean 50.8），
  `q+128 = [158,196]`（mean **178.8**）—— **逐区间吻合**。泛白是 +128，不是 ReLU。
- 反相：因为 XOR 是"模 256 旋转"，它在字节跨越 128 时**非单调**。改动前 ReLU+`qhi=255`
  把 56% 的像素压到 `0x00`、其余顶到 `0xFF`，两者经旋转后落到 **128 和 127（几乎同一档灰）**
  ⇒ 反转被"折叠"成平坦；改动后钳位 [-128,127]，字节只落 `0x8F..0xFF` 与 `0x7F` 两群，
  再经旋转变成 **15..127（暗）与 255（白）** ⇒ 反转**显形**。

### 1.2 四段布局（`INTERFACE.md:231-236`，与 GOLDEN 对拍一致）

### 1.3 L11 的参数是谁生成、用什么公式

**权威公式**（`REFERENCE_PACKAGE_FOUND.md` §4，该节是在拿到参考包后逐项复算的）：

```
W_int[c]  = clip( rint( W[c] / s_w[c] ), ±127 )          # s_w per-channel
b_acc[c]  = rint( b[c] / (s_in · s_w[c]) )  [+ 128·Σw[c]  if 该层输入无符号]
M[c]      = rint( s_in · s_w[c] / s_out · 2^shift )      # 落在 signed int32
mid       = rint( s_skip / s_out · 2^shift )             # 仅残差层
qlo/qhi   = 该层【输出】区间 = 下一层 activation_qrange；末层 = (0,255)
```

同一套公式在工作区的重写版里逐行可读（**仅作对照，不作权威**）：
`blob_export.py:181` `s_w = max|W|/127`；`:241` `m_float = gain*s_w*s_in/s_out`；
`:244` `b_acc = round(biasf/(gain*s_w*s_in))`；`:272` `qlo,qhi = (129,127) if LAYER_SIGNED[i] else (0,255)`；
`:81-105` `pick_shift`（在 int32 内取最大 shift）。

**L11 的实际出处**：【事实】工作区**没有**任何脚本能生成 `0xc7eaf900` 这份 header
（`INK_EXPORT_ROOT_CAUSE.md` §2 全树搜证："只有我自己写的 blob_export.py"）。
【事实】它来自参考交付包，即原始训练/导出链路（该链路未随仓库交付，`INTERFACE.md:6` 自述
"原 `hw/rowpipe/INTERFACE.md` §8 未随仓库交付"，本报告用的是 `starry_cap8_20261024/rtl/INTERFACE.md`）。

## 二、L11 的逐项还原（Σw / bias / M / shift / 每个像素的去向）

### 2.1 L11 的原始字节位置

| 段 | beat | word | 本报告读到的值（redsky_v4 = `.before_l11signed`） |
|---|---|---|---|
| weights | 854–889 | 3416–3559 | 36 beat × 低 3 字节（cout 0/1/2），其余 13 字节全 0 |
| bias | 890–893 | **3560–3575** | `[63695, 59739, 35051, 0 ×13]` ✔ 与 Lead 一致 |
| M/mid | 894–901 | 3576–3607 | M = `[600515771 ×3, 0 ×13]`，mid 全 0 ✔ 与 Lead 一致 |
| quant | 902 | **3608** | `shift=37, qlo=0, qhi=255`（word = `0x003fc025`）✔ 与 Lead 一致 |

> 勘误：任务书里"每 beat 16 字节 = 8 通道 × 2"不成立。真实是**每 beat 16 字节 = 16 个输出通道各 1 字节**，
> L11 的 cout=3 ⇒ 每 beat 只有前 3 字节有效，后 13 字节是硬零填充（本报告逐 beat 校验：pad 非零数 = 0）。

### 2.2 Σw（36 个 tap 逐通道累加，按 int8 解释）

```
c0:  Σw =  699      c1:  Σw =  652      c2:  Σw =  370
```

三通道全为正。按输入通道分组累加（`t = ci_idx*9 + tap`，单位 = int8）：

| ci_idx | 9 个 tap（cout 0） | Σ(ci, cout0) | Σ(ci, cout1) | Σ(ci, cout2) |
|---|---|---|---|---|
| 0 | `[-67, -2, 3, 4, 41, 85, 70, 114, 68]`…（完整 9×3 见附录 B） | 174 | 232 | −52 |
| 1 | — | 236 | 42 | −26 |
| 2 | — | 87 | 126 | 86 |
| 3 | — | 202 | 252 | 362 |
| **合计** | | **699** | **652** | **370** |

（分组求和只是为了让 Σw 可分段复核；判据只看合计。合计与 §2.3 的 `128·Σw` 一致：
`699×128 = 89472`、`652×128 = 83456`、`370×128 = 47360`。）

### 2.3 bias 与 128·Σw 的关系（回答"bias = 63695 是否等于 b_orig + 128·Σw"）

| 通道 | bias | 128·Σw | **bias − 128·Σw = b0** | b0 的物理含义 |
|---|---|---|---|---|
| 0 | 63695 | 89472 | **−25777** | 模型 conv bias，累加器计数 |
| 1 | 59739 | 83456 | **−23717** | 同上 |
| 2 | 35051 | 47360 | **−12309** | 同上 |

判定：**是**。bias 里确实折叠了 `128·Σw`，残差 `b0` 是模型自身的 conv bias。
等价地（这才是可直接用于算像素的形式）：

```
acc_c = b0_c + Σw_c · q_L10        q_L10 ∈ [0,255] 为上一层输出的 uint8 原值
      = [-25777,-23717,-12309] + [699,652,370] · q_L10
```

**零点**：`acc = 0` 分别发生在 `q_L10 = 36.88 / 36.37 / 33.27`。
⇒ 上一层输出低于 ~37（暗部）时 acc<0，高于则 acc>0。

### 2.4 M / shift 的实际缩放

```
m = M / 2^shift = 600515771 / 2^37 = 600515771 / 137438953472 = 4.369327e-3
```

（三个通道共用同一个 M 与 shift，故 m 相同。）

`m` 与"满量程"的关系：

| 量 | 值（shift=37） |
|---|---|
| `m · bias`（即 q_L10=128 时的 DC） | **278.3 / 261.0 / 153.2 LSB** |
| `m · Σw · 127`（conv 项单边满幅） | 387.9 / 361.8 / 205.3 LSB |
| INT8 可用量程 | 256 级 |

⇒ **单是 bias 一项（278 LSB）就已经超过整个 8 位量程**。这就是"缩放大了"的直接证据。

## 三、signed vs offset-binary：证据与判定

### 3.1 证据链

| # | 证据 | 原文/数值 |
|---|---|---|
| 1 | 量化总纲 | `spec.json:16` "activation: **uint8 非对称，ReLU 后非负故 zero-point 恒为 0**" |
| 2 | 每层输入区间 | `spec.json`：12 层中 9 层 `activation_qrange=[0,255]`、`activation_signed=false`；仅 **L5/L7/L9**（输入来自残差加）为 `[-127,127]`、`signed=true` |
| 3 | 输出层区间 | `ref_full_model.py:78-80` 手工追加 `+ [1.0/255.0]` 与 `+ [(0, 255)]` ⇒ **末层输出 = round(y·255) ∈ [0,255]** |
| 4 | 结果帧数值域 | `INTERFACE.md:120-121` "源帧是原始 u8 …… 壳侧**不需要**做任何偏移" |
| 5 | RTL 读取约定 | `rowpipe_engine.v:205` `s_col = xorin ? (src_word ^ {16{8'h80}}) : src_word`；L11 描述符 `xorin=1` ⇒ 无符号输入 |
| 6 | RTL 写入约定 | `rowpipe_layer.v:964` 残差恒等支：无符号张量 `ib ^ 8'h80` 再零扩展，有符号则符号扩展 |
| 7 | 已知可用 blob | L11 = `shift 39, qlo 0, qhi 255`（`INTERFACE.md` §8 表 + 实测 `0x003fc027`） |
| 8 | 中间层存储 | `conv3x3_core.v:20-24`：无符号层 tap 预做成 `t'=t−128`（XOR 0x80），`128·Σw` 折进 bias |

### 3.2 判定

**整条激活链（含输出层）都是 offset-binary uint8 [0,255]，zero_point = 0。**
只有两处是 signed：① int32 累加器；② 残差加法层的输出（L4/L6/L8），区间 `[-127,127]`（注意下界是
**−127 不是 −128**，对称区间）。

- **L11 的正确 `qlo/qhi` = `0 / 255`。**
- Lead 的 `qlo=−128 / qhi=127` 是 **signed 约定**，与权威契约冲突。
- 唯一能让 signed 约定成立的前提，是同时把 `−128·s_out` 折进 bias（即 `b_acc −= round(128/m)`）。
  只改 Q beat 不改 bias = **只做了一半**，这正是"反相"的来源（见第六节）。

### 3.3 为什么"输出层没有 ReLU"不等于"输出层要用 signed"

`ref_full_model.py:138-139` 的判据是 `rng[i+1][0] >= 0`，对 i=11 被 `i+1 < n` 短路 ⇒ 末层不加 ReLU。
但"不加 ReLU"和"用 signed 编码"是两件事：
- 不加 ReLU ⇒ 末层 conv 的实数输出可以略小于 0；
- 编码仍是 `u8 = clip(round(y·255), 0, 255)` ⇒ 略小于 0 的部分被**下钳到 0**（黑），不是变成负码字。
- 硬件上 `qlo=0` 触发的 ReLU 作用在 **acc 域**、在乘 M 之前；因 M>0，
  `clip(relu(acc)·M, 0, 255) ≡ clip(acc·M, 0, 255)`，**与"不加 ReLU + 下钳 0"逐位等价**。

所以 `BLOB_FORMAT.md` §8 bug#3（"L11 标成 ReLU 层 → 输出被半波整流"）**是把偏移域当成了有符号域**，
结论不成立；同理 `blob_export.py:60` 的 `LAYER_SIGNED[11]=1` 是对格式的误读。

## 四、`qlo` 的双重语义（范围下限 vs ReLU 使能）—— 这是不是设计缺陷

### 4.1 两种语义并存的事实

| 侧 | 代码/文档 | 语义 |
|---|---|---|
| 格式 | `INTERFACE.md:234` + spec 的 qrange 链 | 本层**输出**的饱和上下界 |
| RTL | `requant.v:90` / `:114` `(qlo_r < 0) ? a : relu(a)` | `qlo<0` ⇒ 该层输出可以有负 ⇒ 不做 ReLU |
| RTL | `requant.v:159-161` | 同时又把 `qlo` 当饱和下界（符号扩展），`qhi` 零扩展 |

即**同一位域承担两个语义**：`qlo` 既决定"要不要 ReLU"，又决定"下界钳到哪"。

### 4.2 对 11 个中间层：等价，无缺陷

`[0,255]` ⟺（有 ReLU 且下钳 0）⟺ 同一个结果；
`[-127,127]` ⟺（无 ReLU 且钳 −127）⟺ 同一个结果。
`spec.json` 的 `activation_signed` 与 RTL 的 `xorin` 描述符也完全对得上
（signed 的 L5/L7/L9 ⇔ `xorin=0`）。所以导出端是**知道**这件事的，双重语义在中间层是**自洽的压缩**。

### 4.3 对末层：语义分叉，成为真正的缺陷

末层的情况是"输出区间 = `[0,255]`（偏移域），但模型**没有** ReLU"。
- 格式要求 `qlo=0`（下界 0）；
- RTL 读到 `qlo=0` 就**加 ReLU**。
- 如前所述，因 M>0 两者数值等价 ⇒ **本身不出错**。
- **但它给"用 `qlo` 去表达 ReLU"留下了错误的心理模型**：任何人想让末层"不做 ReLU"，
  自然会去把 `qlo` 改成负数 —— 而这一步同时把偏移域强行解释成了有符号域，
  **必须配套改 bias**。今天板上发生的事就是以此为前提的。

**判定：是设计缺陷（可维护性缺陷，不是数值缺陷）。** 具体两条：
1. 位域复用（范围 + ReLU 使能）没有在 `INTERFACE.md §8` 里写明"`qlo<0` 同时等价于 no-ReLU"，
   导致两份文档（`INTERFACE.md` vs `BLOB_FORMAT.md`）对 L11 给出**互相矛盾**的结论。
2. 末层缺一个显式的"输出域"标记（`signed/offset`），使"偏移域 + 无 ReLU"这种合法组合
   无法表达，只能靠"恰好等价"侥幸成立。

### 4.4 顺带发现的第二处缺陷（导出器侧）

`blob_export.py:359` 的模拟器把上限写死成 `hi = min(qhi, 127)`（"qhi is unsigned, store int8"）。
这会让所有 `qhi=255` 的 ReLU 层在仿真里被钳到 127，**与 RTL 逐位不同**。
`INK_EXPORT_ROOT_CAUSE.md` §1 报告的"starry 在模拟器里 L7 有 87% 像素被 ReLU 归零 → 整网坍缩"
正是这个钳位伪影。本报告用它跑 known-good blob 时同样复现了该伪影（L7 钳下界 86.7%），
**所以第二节里的绝对像素统计只对 L11 单层可信，不能当作整网仿真结论**。

### 5.4 M/shift 到底该取多少

约束只有一条（`blob_export.py:81-105` 的 `pick_shift`）：`|M| ≤ 2^31−1`、`shift ≤ 63`，
且 committed 族的经验包络是 `shift ∈ [30,39]`、`|M| ≤ 9.8e8`。
真正的判据是 `m = s_w·s_in/s_out`，要求 **conv 项在 8 位量程内铺满**：

```
要求： m · Σw · (有效激活跨度) ≈ 255
实测： 用一帧真实输入跑 RTL 算术，L11 的 acc 跨度 ≈ 9,738 … 115,024（Δ = 105,286）
⇒      m ≈ 255 / 105286 = 2.42e-3  ⇒ shift ≈ 38.6
⇒      取 shift = 38（m = 2.1847e-3，conv 单边满幅 194 LSB）或 39（97 LSB）
      shift = 37（当前）的 conv 单边满幅 = 388 LSB ⇒ **超量程 1.5 倍**，必然大面积贴轨
```

**建议值：`shift = 38`（首选，利用率 ~76%）或 `39`（保守，~38%），`M` 保持 600515771 不动**
（改 shift 就是改 m，M 字段不必重算，因为 `M/2^shift` 才是有效缩放）。

若要对齐"量程利用率"这个验收口径（`MODEL_OUTPUT_RANGE_FIX.md` §6 要求 σ ≥ 45），
最干净的做法仍是按校准集重算 `s_out`（取实际输出的 p0.5–p99.5），而不是在 blob 上凑 shift。

### 6.1 为什么"去掉 ReLU"会让画面从平坦变反相（机制）

关键：**显示端的 `^0x80` 不是"加 128 的偏移"，而是一个模 256 的 128 级旋转**：

```
byte    0x00 … 0x7F  →  显示 128 … 255   （暗字节 → 亮）
byte    0x80 … 0xFF  →  显示   0 … 127   （亮字节 → 暗）
```

这个映射在字节 128 处**不单调**。于是：

1. **改动前**：字节被 `[0,255]` 钳位铺满整个 0x00–0xFF，旋转已经生效 ⇒ 画面**本来就是反的**；
   但因为 56% 恰好落在 `0x00`、其余挤在 `0xFF`，两者旋转后变成 128 和 127 —— **反转被折叠成一片灰**，
   所以肉眼看是"平坦泛白"而不是"负片"。
2. **改动后**：钳位变小到 `[-128,127]`，字节只落 `0x7F` 与 `0x8F..0xFF` 两群；
   旋转后变成 **255（白）与 15..127（暗）**。两群**不再重叠**，反转第一次可见 ⇒ "负片"。

⇒ **反相不是新产生的，而是原先被"两极同灰"掩盖的 128 级旋转被揭开了。**

### 6.2 对任务书里"负斜率"假设的明确否定

任务书问："是不是因为 bias 里的 `128·Σw` 在 `qlo=0` 时被 ReLU 掩盖了，去掉 ReLU 后暴露出一个
`−Σw` 的负斜率？"

**不是。** 三条硬证据：

1. 三个通道的 `Σw = +699 / +652 / +370`，**全为正**（§2.2，逐 beat 可复算）。
2. bias 含 `+128·Σw`，而 tap 是 `t' = q−128`
   ⇒ `acc = Σw·t' + b0 + 128Σw = b0 + Σw·q` ⇒ 对真实激活 `q` 的斜率 = `+Σw`，**正向**。
3. 逐档扫描（§2.5）在 `qlo=−128` 下给出 u8 = 15→113→211→255，**单调递增**，没有任何递减段。

所以"负斜率"不存在。真正的"翻"来自显示端的 128 级旋转（§6.1），
那是**域不匹配**（偏移域数据 + 有符号显示），不是模型/参数的符号问题。

### 6.3 一句话对账

**板子上的 L11 从未"缩放正确过"**：改动前是"偏移域数据 + 有符号显示"的 +128 LSB 错配（泛白），
改动后是"钳位改了、偏移没改"的半修（反相 + 贴轨）。**两件事要一起改，或一起不改。**
